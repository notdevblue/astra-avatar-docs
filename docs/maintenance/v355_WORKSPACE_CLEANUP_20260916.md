## 다시 작업할 때

**Unity를 다음에 열면 자산 가져오기·패키지 복원·컴파일이 다시 진행되므로 첫 실행은 평소보다 오래 걸릴 수 있다.** 정리 뒤 Unity를 다시 열어 캐시를 재생성하는 검사는 하지 않았다. 현재 Blender 모델이나 보고서·사진·영상을 여는 데는 복원이 필요 없다.

과거 원시 동작 기록을 재분석할 때만 저장소 루트에서 필요한 경로를 복원한다.

```sh
python3 tools/restore_v355_cleanup.py
python3 tools/restore_v355_cleanup.py --restore --prefix avatar_modeling/v349_remaining_npr/physics/
```

첫 명령은 복원 가능한 수량만 표시한다. 두 번째 명령은 지정한 과거 기록만 복원하며, 내용이 다른 기존 파일은 덮어쓰지 않는다. tar.zst에는 `zstd`가 필요하며 현재 Mac에는 설치돼 있다. 이전 v354 정리 자료는 기존 `tools/restore_v354_cleanup.py`, v257 입력 사본은 기존 `avatar_modeling/v257_replay_inputs/restore_inputs.py`를 사용한다.

삭제한 `.venv`의 숫자 프레임 bin은 계산 캐시다. 입력·결과 보고서·생성 코드는 남겨 두었지만 과거 분석 도구를 곧바로 돌릴 때는 해당 프로브를 먼저 재생성해야 한다. 현재 v355 검수 자료는 이 삭제 대상에서 제외했다.

## .git와 남겨 둔 용량

Git은 전체 이력을 재작성하지 않고 `git repack -d -l`로 느슨한 객체만 묶었다. loose 약473MiB가 거의 사라지고 새 pack이 약0.40GiB 추가돼 순효과는 약60MiB 수준이다. 연결 무결성 검사와 multi-pack-index 검증은 통과했고 garbage0이다. 모든 pack 바이트의 full fsck를 했다는 뜻은 아니다.

브랜치·reflog 강제 만료·도달 불가능 객체 강제 prune·대형 pack 직접 삭제는 하지 않았다. 약25GiB 이상의 Git 공간에는 고유한 과거 모델 이력이 있으며, 이후 이번 압축 자료의 백업도 추가됐다. 큰 폴더라는 이유만으로 삭제하지 않는다. 남은 모델·이미지·고유 검증 자료도 같은 기준으로 보존한다.

작업 폴더는 최종 측정 약106.05GiB다. 새 Git 백업과 다른 앱의 디스크 사용 때문에 운영체제 여유 공간은 계속 변할 수 있다. 이번 정리는 모델 수정·어깨 후보 채택·다른 대기 작업 재개가 아니다.
