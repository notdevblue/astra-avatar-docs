# v351 — 연결 UV·분리 텍스처·iPhone 표정 준비 검수

v350의 파편 재배치를 채택하지 않고, 기존 모델의 실제 연결 부위를 기준으로 UV를 다시 폈다. 얼굴·머리·코트·바지·셔츠·손·신발·장식을 각각 편집할 수 있는 8개 이미지와 UV 도면을 만들었다. **기존 형상과 NPR 디테일을 보존하는 작업 사본이며, 전체 아바타 완성이나 사용자 최종 채택은 아니다.**

향후 iPhone 얼굴 트래킹 요청도 제작 기준에 반영했다. 실제 현재 모델에는 얼굴 표정 세트가 없다. 기존 키는 관절 보정용이므로 보존 검사만으로 표정 지원을 주장하지 않는다. [실제 상태와 표정 준비](v351_IPHONE_FACE_TRACKING_PREPARATION.md).

## 1. 실제 적용 전후

아래는 같은 v348 SDK 변형 정점·노멀 기록에 기존 재질과 새 UV/텍스처 재질을 각각 적용한 Unity 사진이다. 새 리그 동작 시험으로 계산하지 않는다. 카메라·광원·포즈는 같다. 각 35구도이며 아래는 첫 6구도다. [전체 35구도 전후 갤러리](v351_POSE_GALLERY.md)와 [12부위 가림 해제 갤러리](v351_SURFACE_GALLERY.md)에서 나머지도 확인할 수 있다.

![기존 v348](images/v351_BEFORE_SHEET_00.png)

![v351 연결 UV와 분리 텍스처](images/v351_AFTER_SHEET_00.png)

얼굴 인상, 머리 컬의 형태, 옷의 접힘과 신발 장식은 원형을 유지한다. 바지 아래쪽의 넓은 밝기와 소매 사각 톤은 v349의 약한 국소 채색 후보를 새 UV에 전사했다. 전체 흐림 필터나 일괄 샤프닝으로 원래 선을 대체하지 않았다.

## 3. 디테일 전사와 숨은 면 검수

원래 삼각형의 새 UV에서 기존 UV로 좌표를 역산하여 색을 옮겼다. 원래 3D 면적이 매우 작은 면은 일반 베이크가 검게 누락할 수 있어 직접 UV 대응 전사도 비교했다. 이 과정은 기존 색의 재배치이며 새 무늬를 그리는 작업이 아니다.

12개 분리 부위를 각각 6방향으로 렌더링했다. 다른 부위를 임시로 숨겨 코트 안쪽·소매·바지 옆/안쪽·신발 밑면·헤어 안쪽을 확인한다. 아래 얼굴 뒷면처럼 내부 면이 드러난 사진은 외관이 아니라 가림 해제 검수다.

전체 샘플 전사의 평균 RGB 오차는 부위별 약 0.027~0.256/255이며, 최종 패킹 UV 겹침 검사에서 유효 교차 면적 0.001픽셀² 초과 쌍은 모두 0이었다. **화면 무손실 또는 모든 텍셀 동일이라는 뜻은 아니다.** 얼굴 최대 74/255와 헤어 최대 122.19/255의 국소 표본이 남는다. 특히 헤어 polygon3205는 원래 3D 공선/기존 UV 압축 구조이며, 해당 표본 오차를 전신 평균으로 감추지 않는다. 아주 얇은 눈 부속·안쪽 경계도 후속 표정 제작 전 구조 검토 대상이다.

## 4. 겹침 0인데 생긴 머리카락 줄무늬의 원인

첫 4K 전사에서 C11/C34의 좁은 면에 반복 줄이 생겼다. 8K로 올리는 것만으로는 충분하지 않았다. 겹침 제거 시 면적이 새 native 전개 수정 전 면적의 10%까지 압축된 것이 주요 원인이어서, 면적 제약과 경계 분리를 다시 풀었다. C11은 80%, C34는 60% 하한 후보가 겹침 없이 통과했다. C34의 80% 시도는 32쌍 겹침으로 거절했다.

큰 줄무늬를 줄인 뒤에도 가는 밝은 사선이 남았다. 독립 검토에서 **실제로 연결되지 않은 열린 경계 주변에서, 문제 표면 샘플과 이웃 면 경계의 거리가 8K에서도 약 0.063픽셀에 불과해 다른 면의 색을 읽는 것**을 확인했다. 바깥 여백만 늘려서는 이미 점유된 이웃 텍셀을 막을 수 없었다.

추가로 C11의 UV 정점 75개가 포함된 국소 최적화를 수행해 두 경계 간격을 확보했다. 원래 모델 정점은 이동하지 않았다. UV 최대 이동은 정규화 전개 좌표 약 0.001178, 국소 면적 하한은 수정 직전의 80%이며 새 겹침은 0이다.

![정상 근접 카메라의 원래 C11](images/local/BEFORE_NORMAL_CAMERA_poly3044.png)

![경계 간격 수정 후 C11](images/local/FILTERGAP_NORMAL_CAMERA_poly3044.png)

독립 역추적에서 기존 ROI의 +3/255 초과 혼입 72픽셀은 0으로 줄었고, 최대 평균 RGB 잔차는 약 12.97→0.424/255였다. 대표 샘플의 4개 보간 텍셀은 모두 원래 어두운 색을 읽었다. [가는 선 원인](v351_c11_thin_line.md).

초기 근접 카메라의 near clip이 표면을 자르는 별도 검수 오류도 발견했다. 위 최종 사진은 near clip을 충분히 줄여 다시 찍었다. 이전 잘린 실루엣을 모델 구멍이나 전사 개선으로 판정하지 않는다.

## 5. 시도와 미채택 이유

| 시도 | 판정·이유 |
|---|---|
| v350 기존 조각 재배치 | 픽셀 보존은 통과했지만 사용자 요청인 연결된 작업 UV에 미달하여 미채택 |
| 원래 quad를 임시 solver에서 그대로 재삼각화 | 원본과 삼각형 분할이 달라 뒤집힘 발생. 원래 실제 삼각형 대응으로 수정 |
| UV 좌표만으로 solver 정점 합치기 | 서로 다른 실제 위치가 합쳐져 C34 겹침 4→113 회귀. 실제 위치+UV 대응으로 수정 |
| 헤어 첫 4K·8K 베이크 | 좁은 면 압축/필터 혼입이 남아 그대로 채택하지 않음 |
| C34 면적 80% 하한 | 겹침 32쌍이 생겨 미채택. 60% 후보는 겹침 0 |
| 헤어 대체 경계 이음선 5개 | 3~5쌍 겹침 및 일부 추가 최적화 회귀. 최종 구성에 합치지 않음 |
| 모든 코트 morph 탄젠트를 새 UV로 재계산 | 원래/새 UV 양쪽에서 일부 handedness 변화. 단순 재계산만으로 정상 노멀 구동을 보장할 수 없어 미채택 |
| 새 UV 코트에 기존 tangent normal 사용 | 좌표계가 달라 그대로 사용하지 않음. 코트는 NPR 색상 위주로 유지하고 tangent 의존 효과를 끔 |

## 6. 모델·관절 보존과 Unity 범위

Blender 최종 재로드에서 기존 두 메시의 정점/면/loop 수, 관절 보정 키 좌표 해시, 129본 목록은 v348과 동일하다. 새 생성·대체 메시, 자동 리메시, 얼굴 형상 변경은 없다.

Unity에서는 UV와 재질 경계 때문에 BodyHair 정점이 32,740→33,752로 1,012개 복제됐다. 실제 원래 정점 대응이며 새 형상을 추가한 것이 아니다. Coat는 3,894개 그대로다. 27,950+3,413개 실제 삼각형의 대응 누락/모호성은 0이다.

저장·재임포트·프리팹 재로드 후 원래 위치/노멀/웨이트/키의 위치·노멀 델타 오차는 0, UV는 지정 값과 동일했다. Coat의 원래 기본/키 탄젠트도 정확히 보존했다. BodyHair는 새 UV 탄젠트와 키의 endpoint 탄젠트를 재계산했다. 이것은 중간·복합 키의 탄젠트가 재계산값과 모든 비율에서 정확히 같다는 보장은 아니다.

신발은 새 UV 좌표계로 원래 형상의 약한 bevel 노멀을 다시 베이크하여 기존처럼 0.15 강도로 사용한다. 코트의 새 UV 노멀 지원은 아직 완료가 아니다. 원래/새 UV 모두 일부 극단 관절 키에서 탄젠트 방향 부호 문제가 있어, 현재 코트는 bump/2nd bump/anisotropy를 끈 NPR 색상 후보로 제한했다.

## 7. 편집 작업성과 메모리 비용

8개 재질 슬롯과 헤어 8K는 편집을 쉽게 하고 작은 선을 보존하는 대신 기존 통합 구성보다 메모리·재질 비용이 늘어난다. 고해상도 작업본을 PC VRChat 최적화 완료본으로 부르지 않는다. Unity Editor 메모리 측정에는 CPU 복사 등이 섞일 수 있으므로 실제 클라이언트 GPU 메모리와 구분한다.

현재 후보의 색상 8장(헤어8K, 4K4장, 2K3장)을 BC7 및 전체 mip으로 저장할 때 블록 데이터만 약 186.7MiB, 신발 2K BC5 mip 약 5.3MiB다. 정확한 런타임 상주량·셰이더 추가 텍스처·드로콜 비용은 별도다. 최종 PC 전달 전에는 작업 원본 해상도를 보존한 채 런타임 크기/압축 후보를 실제 근접·거리·움직임에서 비교해야 한다.

## 8. 얼굴 표정·iPhone 작업으로 이어지는 조건

얼굴 정면을 큰 연결 UV로 유지하고, 눈·입 부속의 원래 정점 대응을 보존했다. 잘못 헤어로 분류됐던 입 내부 88면을 실제 위치·웨이트·가림해제 사진으로 확인해 얼굴 이미지에 재분류했다. 원래 어두운 색은 유지했다.

현재는 얼굴 표정 키 및 눈·턱 전용 본이 없다. 다음 단계는 실제 구조 확인, 좌우 눈감기/시선/눈썹/입술/턱 변형, ARKit 채널 대응, 복합 표정, 기본 깜빡임/eye-look/음성 lip-sync/제스처와의 중복 제어 점검이다. 그 후 iPhone 입력과 PC 수신 경로를 실기로 확인한다. [상세 준비 문서](v351_IPHONE_FACE_TRACKING_PREPARATION.md).

## 9. 남은 작업과 채택 상태

- v351은 UV/텍스처 작업 후보다. v348 원본은 보존했다. 사용자 최종 채택은 별도다.
- 아주 얇은 얼굴·헤어 면의 전사 오차와 중립 안쪽 경계는 표정 제작 전 실제 구조·노출 검토가 필요하다.
- v349 뒷머리–코트의 작은 기존 접촉은 UV 수정으로 해결되지 않는다. 전체 접촉 0으로 표현하지 않는다.
- 새 UV 코트 tangent normal, 런타임 텍스처 예산 최적화, 최종 전체 동작 통합 검수는 아직 남아 있다.
- PC VRChat 클라이언트·월드·네트워크 및 iPhone 얼굴 트래킹 실기는 미검증이다.

파일: `trials/bianca_v351_CONNECTED_PANELS_TRIAL.blend`, `textures/`, `uv/`, Unity `Bianca_v351_ConventionalUV.prefab`. 최종 채택용 패키지와 후속 얼굴 구현을 완료했다고 표시하지 않는다.

## 10. 독립 검토 결과

[최종 시각 검토](v351_FINAL_VISUAL_REVIEW.md)는 전후 12부위×6방향, Unity 35구도, 정상 근접 카메라의 C11/C34를 직접 확인했다. 이번 전사에서 뚜렷한 새 번짐·반복띠·디테일 손실은 식별되지 않았고 눈·입·단추·신발 선은 유지됐다. 소매 흰 커프 끝의 작은 점상 경계와 무릎 뒤 넓은 명암은 전후 공통 잔여다. 이는 표정/모든 거리/새 물리 동작의 최종 합격이 아니다.

[기술 문서 대조](v351_REPORT_INDEPENDENT_REVIEW.md)에서 수치와 미완료 범위를 검토하고 면적/거리의 측정 단위를 정정했다. [C11 최종 기술 검토](v351_filter_gap_final_review.md)에는 실제 텍셀 소유와 최종 파일 대조를 기록했다.
