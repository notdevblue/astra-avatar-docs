# v351 C11 가는 밝은 사선 원인 — 독립 읽기 전용 조사

확인된 원인은 **같은 차트 안에서 서로 다른 실제 열린 경계가 거의 붙어, poly3044의 밝은 텍셀이 poly14019의 경계 샘플에 bilinear로 혼입되는 것**입니다. 겹침 0이라는 검사만으로는 이 필터 오염을 막지 못합니다. 외부 padding 증가만으로도 해결되지 않습니다. 문제의 4개 texel은 이미 정상적으로 각 면에 전사된 occupied texel입니다.

## 정확한 대상

- 사진: `images/local/BALANCED8K_poly3044.png`, ROI (540,175)–(630,365).
- 파일: 최신 `trials/bianca_v351_CONNECTED_PANELS_TRIAL.blend`의 기하/새 UV + **별도** `trials/balanced8k_direct/Bianca_v351_hair.png`. blend 내 다른 bake 색은 진단에 사용하지 않았습니다.
- 실제 선을 받는 면: **poly14019**, 새 UV chart124(의미 영역 C11).
- 혼입 색을 제공하는 면: **poly3044**, 같은 chart124.
- poly14019의 문제 edge 세계좌표:
  - (0.0363769494, 0.0163574982, 0.8730468750)
  - (0.0383300744, 0.0197754689, 0.8833007813)
- 이 edge는 전체 hair TRIANGLES를 검사해도 실제 공유 edge가 아닙니다. poly3044와는 끝점 하나만 공유합니다.
- poly14019의 기존 UV edge는 (0.47582483, 0.94034523)→(0.47582483, 0.92798483)입니다. poly3044 원래 UV는 대략 U0.22,V0.64의 별도 영역입니다. 원래 UV에서 연결된 색 경계가 아닙니다.

## 실제 texel 증거

사진 픽셀 (595,286)을 카메라 기준으로 역투영하면 poly14019 내부이며 barycentric=(0.0004464, 0.6774824, 0.3220712), 새 UV=(0.3239477085,0.8610723861)입니다. 8K에서 이 점의 bilinear 이웃은 다음과 같습니다.

|8K texel x,y|RGB|실제 전사 소유 면|
|---|---|---|
|2653,1137|88,75,73|poly3044|
|2654,1137|66,60,56|poly14019|
|2653,1138|88,75,73|poly3044|
|2654,1138|66,60,56|poly14019|

각 texel 중심이 해당 새 UV 삼각형 내부에 있는 것을 독립 barycentric 계산으로 확인했습니다. 패딩 texel이나 미전사 공백이 아닙니다. query는 poly3044 UV edge에서 겨우 **0.06274 texel** 떨어져 있습니다. 두 실제 경계의 새 UV 방향 차이는 **약0.0213도**로, 같은 끝점에서 거의 겹쳐 뻗습니다. UV 내부 겹침이 없더라도 bilinear의 4texel footprint가 양쪽 면을 함께 읽습니다.

동일 실제 면을 원래 UV로 직접 읽으면 RGB(66,60,56)인 지점이 새 atlas bilinear에서는 약(81.85,70.81,68.25)이 됩니다. ROI의 양의 평균 RGB 잔차 상위50개가 모두 poly14019 경계에 있습니다. 진단 최대 평균 잔차는 약+12.97/255입니다. 이 수치는 저장된 sRGB 값에 대한 Python 보간이며 Cycles의 선형 색공간/AA까지 완전히 재현한 화면 오차 수치는 아닙니다. 그러나 소유 면이 다른 4texel의 혼합은 직접 확인됐습니다.

## 무엇이 원인이 아닌가 / 어디까지 확정했나

- poly3044의 미세 삼각형 문제와 관련은 있지만, 현재 선이 보이는 픽셀은 poly3044 자체가 아니라 **이웃 공간의 poly14019**입니다.
- 전사 수식이 poly14019 내부의 색을 잘못 가져온 사례가 아닙니다. 오른쪽 texel은 원래 색과 맞고 왼쪽 texel은 각자의 poly3044 원래 UV 색을 갖습니다.
- 기존 source에서 두 면의 색은 다릅니다. 새 UV가 실제 비연결 경계를 필터 폭 이내로 배치하여, 원래 별도 UV에서 분리되어 있던 색이 새로 섞이는 것이 이번 사선의 원인입니다.
- 전체 smoothing/샤프닝/색 덮어쓰기로 처리할 이유가 없습니다.
- 12px 외부 gutter는 이미 occupied인 poly3044 texel을 바꾸지 못합니다. 여기에는 chart 사이 padding이 아니라 **동일 chart 내부의 서로 다른 열린 경계 간 거리** 제약이 필요합니다.

## 원인에 맞는 수정 후보

1. C11 열린 경계/내부 좁은 틈에 최소 texel 거리 또는 최소 각도 제약을 넣어 국소 UV만 조정합니다. 공유 끝점 바로 근처의 간격은 원리상0이므로 꼭짓점 범위를 별도로 허용하고, 그 외 유효 길이에서 bilinear/mip footprint를 확보해야 합니다.
2. 한 차트 내부 배치로 충분한 간격과 기존 밀도를 함께 보장할 수 없다면 문제 구간을 의미 있는 seam으로 분리해 독립 padding을 둡니다. 원래 메시/형상/노멀을 바꿀 필요는 없습니다.
3. 재전사 후 같은 4texel 소유 검사, 같은 ROI, clip을 정상화한 다른 실제 시점, 밉/축소에서 검증합니다. 해상도만 올리는 것은 현재처럼 경계 간 거리가 거의0인 경우 보장이 아닙니다.

## 로컬 카메라의 별도 검수 함정

`render_hair_local.py`는 카메라를 center+normal×0.1m에 두지만 새 Camera의 기본 clip_start도0.1m입니다. 따라서 target 중심면에서 가까운 쪽 표면이 near clip으로 잘립니다. 처음 near clip 없이 만든 analytic image는 원본 local screenshot과 맞지 않았고, 실제 near clip을 적용한 뒤 해당 형태와 선이 재현됐습니다. 현재 보고서의 픽셀 대응은 **실제 clipping을 반영한 결과**입니다.

향후 로컬사진은 clip_start를 충분히 작게 설정하는 것이 맞습니다. 지금의 잘린 실루엣/노출 관계를 전체 모델의 실제 외형으로 판정해서는 안 됩니다. 이번 UV texel 혼입 원인은 카메라 clipping과 별개로 존재하지만, 정상 카메라에서 해당 면이 얼마나 보이는지는 다시 확인해야 합니다.
