# v349 / v351 작업 보고 최종 독립 검토

중대한 완료 범위 과장은 발견하지 않았습니다. 게시 전 수정 권장 사항은 아래 두 표현입니다. 프로젝트 파일은 수정하지 않았습니다.

## 1. v351 4절 — “원래 UV의 10%”의 기준이 잘못 읽힘

현재 문장: “겹침 제거 시 면적이 원래 UV의 10%까지 압축된 것이 주요 원인이어서…”

`relax_hair.py`의 입력은 v343 원래 UV가 아니라 **새 native 전개 결과 `*_HAIR_UNWRAP.json`**입니다. 면적 하한은 각 최적화 step의 `start` 면적에 대한0.1입니다. C11/C34의 해당 면은 새 전개의 초기 면적 대비 약10%가 된 것이며, v343 원래 atlas 면적과 직접 비교한 수치가 아닙니다. `relax_hair_area_trials.py` 역시 `*_HAIR_UNWRAP.json`을 복원한 뒤 후보를 시험합니다.

권장 표현: “새 전개 결과의 겹침을 제거하는 과정에서 일부 면이 **해당 새 전개 수정 전 면적의 약10%**까지 압축된 것이 주요 원인이어서…”

또한 C11의80%/C34의60%가 v343 원본 UV 면적 보존율이라고 읽히지 않도록 “새 전개에 적용한 면적 하한”임을 붙이면 좋습니다. 현재 뒤쪽 필터 간격 문단의 “수정 직전의80%”는 정확합니다.

## 2. v351 4절 — 0.063픽셀은 정확한 두 경계 간격 수치가 아님

현재 문장: “실제로 연결되지 않은 열린 두 경계가 8K에서도 약0.063픽셀 거리로 붙어…”

독립 진단의0.0627398픽셀은 **문제가 보인 poly14019 내부 query에서 poly3044 경계까지의 최단 거리**입니다. 두 열린 경계 자체의 간격으로 직접 측정한 값은 아닙니다. query가14019의 경계 바로 안쪽이므로 원인 설명은 맞지만 수치 정의를 정확히 해야 합니다.

권장 표현: “서로 다른 열린 경계가 거의 붙어, 문제가 보인14019의 표면 샘플이8K에서도 이웃3044 경계에서 약0.063픽셀밖에 떨어지지 않았고 다른 면의 색을 읽는 것을 확인했다.”
