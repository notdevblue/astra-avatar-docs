# v345 NPR 재작업 계획과 독립 검토 절차

상태: **계획·절차만 정리. 모델·텍스처·UV·노멀·셰이더 수정과 검토 에이전트 실행은 보류.** 사용자가 “작업 바로 하지 말고 리스트업 먼저”라고 정정했고, 이후 별도 검토 에이전트 절차를 추가하도록 요청했다. 이 문서 작성은 제작 착수를 의미하지 않는다.

## 목표와 현재 판정

목표는 photorealistic 표현이 아닌, 고품질 애니메이션·일러스트에서 나온 듯한 NPR 캐릭터다. 원래 캐릭터 인상·실루엣과 단추·봉제선·장식·머리 가닥의 의미 있는 디테일을 보존한다. 흐린 반사와 불규칙한 얼룩을 디테일로 간주해 모두 유지하지 않는다.

v343은 보존할 비교 기준이며 텍스처 완성본으로 취급하지 않는다. 사용자 표시 사진에서 팔·다리 안쪽과 코트 옆/안쪽의 얼룩이 남았고, 헤드 텍스처도 전체 재작업 대상이다. v004의 고정 그림자 감소는 코트 앞 4패널 시험, v344는 제한을 명시한 관절·물리 검사 기록이다. 자료 작성·검사 실행과 시각적 해결을 구분한다.

추가 일러스트는 선·색면·명암 설계 참고다. 머리 길이·얼굴 인상·체형을 그대로 이식하지 않는다. SiuSiu는 2D 재질 표현 참고이며 기존 캐릭터의 디자인을 대체하지 않는다. 승인된 무릎 형상과 손가락 국소 압축은 유지한다. 새 메시 생성·부분 대체·자동 리메시는 하지 않는다.

| B · 셰이더 명암 중심 | 큰 고정 그림자를 줄이고 광원에 따른 툰 명암으로 표현 |

기존 색의 밝고 어두움을 그대로 높이로 변환하는 방법이 적절한지도 조사한다. 이를 물리적으로 올바른 요철로 미리 가정하지 않는다. 같은 광원의 좌/우/위 방향·밝기 변화, 팔 올리기·다리 굽히기, 전신 거리·확대를 비교한다. 노멀을 추가한 사실 자체를 개선으로 세지 않는다.

## 헤어·넥타이 움직임 개선 — 추가 요청

사용자는 머리카락과 넥타이가 뻣뻣하고 거의 움직이지 않는다고 지적했다. 기존의 “동작 검사” 항목에 더해 **움직임 자체의 개선 작업**을 별도로 추가한다. 현재는 목록 반영만 하며 본·물리 설정 편집은 시작하지 않는다.

기존 v343 Unity 검수 프리팹과 v344 검사 기록에서 넥타이는 `tie_anchor → tie_01 → tie_02 → tie_03 → tie_tip` 구조다. 가운데 3개는 변형 본이며 `tie_01`에 PhysBone 1개가 기록되어 있다. 헤어에는 PhysBone 6체인이 있다. 따라서 우선은 본 부재보다 현재 구성에서 움직임이 작은 원인을 확인한다. 제작 시 실제 출발 파일을 다시 확인하고, 넥타이 본이 없는 사본이면 사용자의 조건부 요청에 따라 기존 메시용 본·웨이트·물리 구동을 구성한다. 불필요한 중복 본을 만들지 않는다.

| 단계 | 작업 |
|---|---|
| 실제 구동 확인 | 본 계층·영향 정점·고정 영역·PhysBone 활성 상태 확인. Animator/제약이 물리 결과를 덮는지, 콜라이더·회전 제한이 움직임을 지나치게 막는지 분리 |
| 원인별 비교 | 복원력·감쇠·관성 반응·각도 제한·충돌 여유 및 웨이트 분포를 후보별로 비교. 아직 원인을 특정 설정 탓으로 단정하지 않음 |
| 헤어 개선 | 머리 회전·끄덕임·몸 이동·정지에 가닥 끝이 자연스럽게 지연·복귀하도록 조정. 뿌리와 기본 실루엣을 지키고 얼굴/어깨 관통·과한 출렁임 검사 |
| 넥타이 개선 | 매듭 부근은 안정적으로 유지하고 아래 몸통·끝에 움직임 분담. 가슴·셔츠·코트 관통, 늘어남, 매듭 이탈 검사 |
| 기존/후보 비교 | 기존·약한 개선·중간 개선 등 사본을 같은 입력/시간/카메라/재질로 비교. 적합한 진폭과 안정성을 보고 선택 |
| 동작 자료 | 머리 회전, 좌우 이동, 출발/정지, 방향 전환, 숙임, 바람 파라미터를 분리한 전신 및 헤어/넥타이 확대 GIF 또는 영상 |
| 안정성·재검토 | 바람/이동을 멈춘 뒤 자연스러운 감쇠·복귀를 먼저 검사. 강제 리셋은 별도 검사로 기록. 연속 진동·떨림·관통·UV/명암 깨짐 확인 |

목표는 단순히 크게 흔들리는 것이 아니라 NPR 캐릭터에 맞게 **평상시 움직임도 읽히면서 형태가 안정적인 반응**이다. 기존 작은 회전 수치나 유한 정점 검사만으로 “충분히 움직인다”고 판정하지 않는다. 이전 GIF가 같은 동작에서 텍스처만 비교했다면, 이번에는 **실제 리그/물리 후보의 움직임 차이**를 비교한다. 바람 FX 파라미터와 월드 바람 감지는 구분한다.

시각 검토 에이전트는 움직임이 눈에 읽히는지·머리 인상·과장·정지 후 잔떨림을 확인한다. 기술 검토 에이전트는 본/웨이트/물리/Animator 연결·충돌·복귀 조건을 대조한다. 두 검토자 모두 정지 사진만으로 동작을 합격시키지 않고 실제 영상/GIF를 확인한다.

## 독립 검토 에이전트 역할

| 역할 | 책임 | 편집 권한 |
|---|---|---|
| 작업 담당 | 제작, 재현 가능한 비교 사본·렌더·측정 자료 준비, 지적 사항 수정 | 작업 사본 편집 및 결과 통합 |
| 시각 검토 에이전트 | NPR 일관성, 번짐·얼룩, 디테일 손실, 숨은 면 누락, 캐릭터 인상·실루엣·부피감 변화 | 검토 전용. 모델·텍스처·셰이더 직접 수정하지 않음 |
| 기술 검토 에이전트 | UV 밀도·왜곡·이음선, 노멀 방향·강도·가져오기, 그림자 분담, 원형·본·웨이트 보존, 검사 범위와 완료 주장 | 검토 전용. 원본·사본 및 검사 데이터를 읽어 대조 |

두 검토자는 서로의 결론을 보기 전에 첫 판단을 각각 작성한다. 작업 담당은 사용자 요구·원래 레퍼런스·추가 참고 이미지·전후 실제 렌더·촬영 조건을 제공하되, 첫 시각 판단 전에 “개선됐다” 같은 자기 평가로 유도하지 않는다. 기술 검토에는 대응 UV·설정·원본/사본·검사 방법을 함께 제공한다. 첫 판단 이후 작업 의도와 구현 이유를 공유해 원인을 대조한다.

실제 검토는 제작 재개 후 독립적으로 수행할 수 있는 범위로 나눠 배정한다. 현재는 에이전트를 생성하거나 실행하지 않는다.

## 검토 시점과 재검토

1. **기준 자료 검토:** 제작 시작 시 요구 사항·문제 위치·필수 시점을 점검한다. 미확인 면과 근거가 부족한 판정을 표시한다.
2. **부위별 중간 검토:** 헤드, 팔/코트 안쪽, 다리/신발 및 헤어·넥타이 움직임의 첫 후보를 각각 검토한다. 전체 제작 종료까지 문제를 쌓아두지 않는다.
3. **방식 선택 검토:** 그림자·노멀 A/B/C/D 사본을 같은 조건에서 대조해 장단점과 미채택 이유를 남긴다.
4. **통합본 검토:** 최종 텍스처·UV·셰이더를 함께 적용한 실제 관절 사진과 움직임 자료를 본다. 정지 화면의 합격을 동작 합격으로 확대하지 않는다.
5. **수정 후 재검토:** 지적 부위의 동일 구도와 인접 면·반대쪽·관련 자세를 다시 비교한다. 문제 해소와 다른 부위 회귀 여부를 확인한다.
6. **전달 전 검토:** 문서·사진·영상·전달 파일이 같은 버전인지, 남은 문제와 미검증 범위를 정확히 적었는지 확인한다.

검토가 진행되는 동안 작업 담당은 겹치지 않는 부위나 자료 정리를 진행할 수 있다. 지적 사항과 직접 관련된 수정은 검토 결과를 반영한다. 두 검토자가 같은 파일을 수정하도록 배정하지 않는다.

## 지적 사항 기록 양식

각 항목은 `VIS-001` 또는 `TECH-001` 같은 고정 ID를 사용하고 다음 내용을 남긴다.

| 필드 | 기록 내용 |
|---|---|
| 근거 | 실제 사진/GIF 프레임·부위·방향·자세, 가능하면 UV/재질/면 대응 |
| 관찰 | 무엇이 보이는지, 레퍼런스·원본·수정본의 차이 |
| 영향 | 얼룩·디테일 손실·인상 변화·원형 회귀 등 사용자 목표에 미치는 영향 |
| 원인 | 확인된 사실과 추정을 구분. 불명확하면 미확인으로 표시 |
| 조치 | 수정 방향 또는 추가로 필요한 검사 |
| 결과 | 미해결 / 수정 후 재검토 필요 / 해소 확인 / 유지 근거 기록 / 판단 불일치 / 미검증 |

문제를 지적한 검토자가 수정본을 다시 확인한다. 불가능하면 다른 독립 검토자가 같은 근거로 재검토하고 담당 변경을 기록한다. “이상 없음”도 실제 확인한 부위·시점·검사 범위를 함께 적는다. 이미지를 보지 못했거나 자료가 없으면 합격으로 처리하지 않는다.

## 완료 판단

- 사용자 표시 부위를 같은 자세에서 다시 보고 결과를 항목별로 남긴다.
- 미해결·미검증은 완료 목록에 넣지 않는다. 면 목록 누락 0이나 검사 실행 횟수만으로 시각 품질을 합격시키지 않는다.
- 검토자 간 의견이 다르면 작업 담당이 증거를 대조하고 추가 비교한다. 해결되지 않으면 양쪽 의견과 차이가 보이는 자료를 함께 공유한다.
- 독립 검토자의 합격은 사용자 최종 채택을 대신하지 않는다. 해결한 항목과 남은 미적 선택을 구분해 전달한다.
- 모든 실험을 버전 사본에 보존하며 실패안과 선택 이유도 기록한다.

이번 문서는 절차 추가와 누적 요청 정리 결과다. 새 모델·텍스처·UV·노멀·셰이더 실험, 검토 에이전트 실행, 관절 재검사는 수행하지 않았다.
