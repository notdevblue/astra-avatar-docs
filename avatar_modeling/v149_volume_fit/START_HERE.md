# v149 — 연속 두께 복원과 접촉 제한 실험

**비교·최적화 실험 폴더다. RAW/FIT/VECTOR 파일을 최종 통과본으로 해석하지 않는다.** 원본 모델은 v146이며 새 캐릭터 메시를 만들지 않았다. 최신 비교 문서는 [v152](../v152_volume_review/START_HERE.md)를 우선한다.

## 방법

v148 DEPTH 60·90·120 목표에서 좌우 6개 키를 만들었다. 팔 컨트롤의 quaternion으로 전방 회전각을 구하고 구간별 선형 가중치로 키를 혼합한다. quaternion 부호와 배율에 의존하지 않는 식을 사용하며, 측방·비틀기 감쇠와 기존 몸통 게이트를 적용한다. Python driver namespace 등록이 필요한 사용자 함수는 쓰지 않는다. 게이트와 저장 모션은 최종 파일에서 다시 검사해야 한다.

## 크기만 제한한 실험

실제 Blender에서 키 OFF/ON 좌표·교차 쌍·면적 경고를 취득했다. 분리된 두 삼각형의 기준 자세 분리 축을 구하고, 새 보정이 그 간격을 침범하지 않도록 sparse QP로 투영했다. 한 정점의 세 각도 보정에 동일 진폭을 사용했다.

첫 제한 후 앞90 두께는 약91%였지만, 새 면적 경고와 이웃 면 교차가 남았다. 두 번째 제한 후 두께는 약78%로 낮아졌다. 정점을 동결하는 방식은 경계로 찌그러짐을 옮기는 한계가 있어 **이 진폭 제한 FIT를 최종으로 선택하지 않았다.**

## 이동 방향까지 조절한 실험

30개 전방 각도·비틀기 조합에서 실제 LBS 선형 응답과 키 값을 저장했다. 기존 493정점 × 3각도 × XYZ = 4,437개의 이동 성분을 변수로 두었다. 목표 변형에 가깝게 유지하되 이웃 정점 간 변화가 급격해지지 않게 하고, 기존 삼각형의 분리 평면 조건과 면적 비율의 순차 선형 근사를 적용했다.

면적 제한에는 유한한 페널티를 사용한다. 따라서 **최적화가 solved라고 나와도 실제 모델 검사 통과를 뜻하지 않는다.** 실제 Blender 재평가 결과를 `FIT_CAPTURE_VECTOR*.json`에 별도로 남긴다. 면적 근사의 내부 잔여 수치는 실제 임계값 경고 수와 다르다. 이미 기준에서 겹치는 삼각형, 동적 사각형 분할이 바뀌는 사례는 단순 분리 축으로 보장할 수 없다.

첫 방향 보정은 앞90 두께 약92%, 새 면적0, 새 접촉42였다. 전체 접촉은363→355였지만 위치가 달라진 새 접촉이 있어 추가 투영을 진행했다. 총 접촉 감소만으로 새 문제를 숨기지 않는다.

PASS3은 앞90 두께89.9%, 새 접촉2까지 줄었다. PASS4는 면적 페널티를 강화했다. PASS5는 기준 면 방향 조건을 추가하고 이동 신뢰 구간을6mm에서2mm로 줄였다. PASS6는 좌우 어깨선 proxy(6726→6727→6728→6732, 대칭2711→2720→2748→2747)의 길이를 기준 대비 상한1.002로 제한했다. 앞90 길이 비율은 v146의1.148/1.064/1.397에서1.142/1.066/1.393으로 맞춰졌고 두께는89.8%를 유지했다. 면 방향·면적은 여전히 유한 페널티이며 모든 잔여 교차를 해결한 것은 아니다.

`VECTOR_PASS4.npy`, `VECTOR_PASS5.npy`, `VECTOR_PASS6.npy`에 중간 변형을 보존했다. `VECTOR.npy`와 VECTOR/GATED blend는 마지막 PASS6이다. PASS별 실제 재평가는 `FIT_CAPTURE_VECTOR1~6.json`에서 확인한다. v150 정점 고정은 미채택이고 최종 후보에는 포함하지 않는다. v151은 PASS4 보존 검사용 중간본, v152는 PASS6와 swing 게이트의 비교 후보다.

전방 각을 quaternion의 X 성분만으로 읽으면 옆 거상+비틀기에서 약0.95mm 보정이 섞였다. 실제 팔 축의 전방 성분 `-2*(c*d+a*b)/norm`을 추가 확인하는 연속 게이트로 옆/뒤 키값0을 확인했다. 전체 각 추출 식을 바꿔 기존 학습 응답을 무효화하지 않고, 이 분류 조건을 더했다.

## 구현과 재현

- `00_build.py`: 원본 보존, 연속 키 RAW 작성
- `01_capture.py`: 8각도 OFF/ON 응답
- `02_fit.py`, `03_apply_check.py`: 진폭 투영과 실제30자세 재검사
- `04_linear_response.py`: 실제 본 변환과 키 가중치 취득
- `05_vector_fit.py`: 이동 방향 투영, 자료에 기록된 접촉 쌍을 누적
- `06_vector_check.py`: 실제 Blender 재평가, 다음 반복용 새 교차 수집
- `07_trial_render.py`: 같은 카메라의 v146/첫 VECTOR 뒤사선·측면

실험 반복 데이터와 중간 오류는 MCP 로그 및 JSON에 보존했다. 최적화 중 신뢰 구간 안에서 실행 불가능한 제약, solver 반복 한도, 면적 제한의 반복 진동을 확인해 변수를 확장하고 면적 제약 누적·정규화·warm start를 적용했다. 최종 검사와 중간 실패를 구분한다.

[OSQP Python API](https://osqp.org/docs/interfaces/python.html), [solver 설정](https://osqp.org/docs/interfaces/solver_settings.html)을 참고했다. 작업용 Python 라이브러리는 `.venv/fitlibs`에 설치했으며 모델 실행에 필요한 의존성으로 추가한 것이 아니다. 이 키의 Blender 작동 확인은 Unity/VRChat에서의 드라이버 실행이나 천 물리 완성을 뜻하지 않는다.
