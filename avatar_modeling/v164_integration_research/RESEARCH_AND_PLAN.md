# 비앙카 관절·의상·Unity 통합 조사와 실행 계획

기준은 v163 정적 검수본이다. 기존 캐릭터 정점과 형태를 수정하는 범위에서 진행하며, 새 캐릭터 생성과 메시 재생성은 하지 않는다. 큰 구조 실험은 별도 파일로 비교한다. 실제 VRChat 접속·업로드·Build & Test는 이번 범위에서 제외한다. Unity Editor 안의 Humanoid, 제약, 물리, 애니메이션 검사는 포함한다.

## 1. 지금 확실한 것과 다시 확인할 것

실제 v163 파일을 Blender MCP로 다시 열어 두 메시, 본 계층, 실제 양수 웨이트, 제약, 모든 드라이버를 추출했다. 현재 상태 (공유본 미포함: `CURRENT_STATE.json`). 원본 이미지 `avator_references/ref_char.png`를 열어 각진 정장 어깨선, 라펠, 닫힌 긴 소매, 코트 자락, 짧고 여러 덩어리로 겹친 헤어를 확인했다. 이런 의상은 피부처럼 모든 점이 상완을 따라 부드럽게 흐르는 것을 목표로 하면 원래 재단이 무너진다.

v163의 32,773정점, 17,648면, 118본과 기존 키는 출발점이다. 코트는 1,736정점으로 분리되어 있다. 헤어·카라 개선과 코트 분리 전후 일치 검사는 완료됐지만, 앞 들기의 소매산 압축과 겨드랑이 홈, 오른쪽 손목 복합 회전이 남는다. 이전 수치에서 감소한 경고 수를 전체 해결로 해석하지 않는다. 검사한 자세가 많다는 사실도 모든 동작 품질의 보증은 아니다.

소매 끝의 실패 면은 주로 코트다. v162는 주로 **전완 영향 일부를 새 반회전 본으로 옮겼다**. 손 본의 굽힘 영향은 남아 있으므로, 새 Twist가 올바르게 돌아도 코트 끝의 굽힘·비틀기 혼합은 여전히 나빠질 수 있다. 이번에는 이 두 입력의 역할을 분리해 검증한다. 이 설명은 실험 전 가설이며, 실제 웨이트와 대조 결과로 확인한다.

## 2. 문서·튜토리얼에서 얻은 근거

### 굽힘과 비틀기, 보정의 입력 공간

Autodesk의 Pose Editor는 Swing, Twist, Swing and Twist를 구분한다. 팔을 든 상태에서 비틀더라도 가슴 보정을 유지해야 하는 경우와 손목이 굽혀져도 전완 비틀기 보정을 유지해야 하는 경우를 구체적으로 설명한다.[1] 비앙카의 기존 8도 굽힘 게이트처럼 보정을 거의 꺼버리는 방식은 회귀를 숨길 수 있으므로 완성 기준으로 삼지 않는다. 전완축으로의 quaternion 투영과 본의 rest 공간을 확인하고, 단독 회전뿐 아니라 굽힘+비틀기 조합에서 검증한다.

CGDive 제작자의 공개 영상은 팔꿈치, 무릎, 어깨의 corrective shape key와 회전 드라이버를 다룬다.[2] Chrome에서 제작자 설명과 챕터를 직접 확인했다. 0:14 팔꿈치 키, 4:26 드라이버, 7:31 곡선, 11:32 무릎, 15:09 어깨다. 이 원리는 현재 메시의 잔여 변형을 자세별로 수정하는 데 적합하다. 다만 해당 Blender 절차가 FBX와 VRChat에 그대로 작동하는 해결책은 아니다. 설명·챕터 확인을 영상 전체 시청이나 자막 전체 분석으로 기록하지 않는다. 표시된 스크립트는 로딩 상태였고 자막 사용 불가였다.

P2design의 corrective shapekeys 강의도 확인했지만 유료 강의 본문을 열람한 근거로 쓰지 않는다.[3] Dikko의 Body Retopology 강의는 어깨·팔·목 구간을 추가 학습 후보로 찾았으나 원본 영상 본문 확인이 부족해 구체적 설계의 근거로 채택하지 않는다. 튜토리얼 목록의 양보다 현재 모델에서 재현되는 결과를 우선한다.

### 면 흐름과 삼각화

단순히 사각면을 늘리거나 삼각면을 없애는 것이 목표가 아니다. 실시간 스키닝은 실제 삼각면 연결에서 평가해야 한다. 비평면 사각면의 대각선이 Blender 평가와 FBX/Unity 사이에서 달라지는지도 확인해야 한다. 따라서 기존 각 면의 정점 수와 기본 자세에서의 삼각화를 기록하고, 포즈마다 변하는 평가 삼각화와 고정 삼각화를 구분한다. 이 차이를 면적 경고의 감소로 오인하지 않는다.

우선 변경하지 않은 면과 변위 바깥의 영역을 보호하며, 문제 면 주위에서 웨이트 급변, 길고 좁은 삼각형, 여러 면이 한 점에 모인 위치, UV/노멀 경계를 확인한다. 수정은 원래 정점의 국소 연결·보조 컷·보정 중 가장 적은 변화로 한다. 정지 상태의 선과 주름을 지우는 전체 평활화는 채택하지 않는다. Blender의 Armature/Corrective Smooth 문서는 이번 web 열람에서 접근 오류가 있었으므로 본문을 새로 확인했다고 쓰지 않는다. 기존 v147–155 실험과 실제 모디파이어 결과가 그 대안을 판단하는 직접 근거다.

### 물리와 의상 역할

VRChat 공식 PhysBones는 제한 각, 복원력, 충돌 대상을 별도로 설정하며 제약과 PhysBone이 같은 Transform을 동시에 제어하지 않도록 안내한다.[4] 강체 몸판과 움직이는 자락을 나누고, 필요한 경우 부모에 제약/바람 입력을 둔다. 헤어에 큰 컬라이더를 넣어 정지 상태부터 밀어내던 v160 실패를 반복하지 않는다. 원형 복귀와 물리 OFF/ON의 실제 표면 차이, 자락과 다리의 접근을 측정한다.

Sipp's Avatar Box PhysBones 영상[5]과 ABDE in VR 헤어 영상[6]을 다시 찾았다. 전자는 Chrome에서 원본 페이지가 열렸으며, 이전 v158에서 기록한 뿌리·힘·제한·충돌 챕터를 현재 공식 문서와 대조한다. 후자는 이번 직접 fetch에 실패했다. 두 영상의 오래된 UI/설정값을 SDK 3.10.5의 권장값으로 그대로 복사하지 않는다.

### Unity 실행과 VRChat 제약

VRChat Rotation Constraint는 소스, 축, rest/offset, 로컬 공간 옵션을 제공한다.[7] 본 이름과 회전 비율만 복제하지 않고 Blender의 부모/rest 행렬과 Unity 결과를 맞춘다. 공식 허용 컴포넌트 문서는 임의의 사용자 스크립트가 아바타에서 작동하지 않는다고 명시한다.[8] 따라서 진단용 C#으로 Blender 드라이버를 재현한 것만으로 VRChat 이식 완료를 선언할 수 없다.

Contacts는 자신의 Sender/Receiver 근접도에 따라 Animator 파라미터를 갱신할 수 있다.[9] 본에 붙인 측정용 Transform과 자기 자신만 받는 태그를 사용하면 관절 자세에 따른 보정 입력을 만들 수 있지만, 센서의 사각지대, 역방향, 전신 회전, 프레임 지연과 성능 비용을 검사해야 한다. 이는 임의 quaternion 수식의 자동·정확한 변환이 아니다. 실제 SDK에서 재현해 오차를 측정한 뒤 채택한다. 일반 C#은 비교 기준 계산과 Editor 검사에만 사용하고, 배포 아바타에 필요한 구동은 허용 컴포넌트로 구성한다.

## 3. 구매 모델과 비앙카의 차이

v156–158에서 추출한 실제 본·웨이트·프리팹 제약·PhysBone 연결과 v157 실행 데이터를 재검토했다. 이번에도 구매 모델의 뒤쪽 팔 자세 비교 이미지를 열어 확인했다. 구매 자산과 상세 좌표는 로컬 `.venv`에 두고 Git에 복사하지 않는다.

| 비교 대상 | 직접 확인한 구현 | 비앙카 적용 판단 |
|---|---|---|
| SiuSiu 블레이저 | 몸판 윤곽을 남기고 소매가 움직임. Standard 전완 Twist 실제 구동, Kisekae는 같은 방식으로 작동하지 않음 | 어깨 몸판과 소매를 같은 강도로 회전시키지 않음. 이름/메시가 같다는 이유로 실행을 가정하지 않음 |
| Lapwing 볼레로 | 몸판·상완·늘어진 소매 역할 분리. 팔꿈치·무릎 보조본과 의상 제약 | 보조본은 실제 웨이트가 붙는 범위가 핵심. 넓고 열린 소매의 자유도를 정장 소매에 복제하지 않음 |
| SiuSiu 헤어 | 짧은 체인별 회전 제한, 헤어 일부는 명시 Collider 목록 없이 작동 | 짧은 헤어는 제한과 뿌리 고정부터. 충돌체 개수로 완성을 판단하지 않음 |
| Lapwing 헤어/의상 | 길이와 부위에 따른 Collider 연결 | 코트 자락은 골반·다리와의 실제 상대 이동을 검사 |

참고 모델도 주름과 접촉이 있다. 옷 속 몸체 일부가 생략된 경우도 있어 관통이 적게 보이는 이유를 전부 우수한 웨이트로 해석하지 않는다. 비앙카의 정장 어깨선은 남기되 팔 움직임에 따라 부자연스럽게 이동하거나 너무 늘어나는 부분을 줄인다.

## 4. 실행 순서와 판정 기준

1. **분리 메시용 진단 기준 확립.** 기존 단일 메시용 검사 함수의 component/index 가정을 제거한다. 원본 ID로 전체 정점·면을 대응시키고, 현재 두 객체의 실제 평가 좌표와 삼각화를 취득한다. 중립, 앞/뒤/옆 들기, 손목 복합 회전, 목/허리/하체/손가락의 입력과 카메라를 고정한다.
2. **소매 끝 입력 분리.** 기존 손 굽힘이 코트에 기여하는 범위를 조사한다. 손 영향의 전완 이전, 손 굽힘만 제거한 소매 전용 roll, 국소 면 보정 등을 각각 분리 시험한다. 손·손가락은 보호하고 순수 비틀기 개선과 복합 굽힘 회귀를 따로 집계한다.
3. **어깨·카라·겨드랑이 국소 작업.** 몸판 지지, 소매산 회전, 겨드랑이 접힘 경계의 실제 면을 조사한다. 기존 v152 두께 복원과 카라 개선을 보호하며 과도한 압축/길이 변화를 다자세로 줄인다. 보정 OFF/ON과 기본 면 구조를 비교하고, 회귀 면이 반복되면 해당 연결을 직접 수정하는 별도 후보를 만든다.
4. **코트 물리와 전신 복합 자세.** 기존 앞/뒤 네 자락 체인에 실제 물리를 연결하고, 필요하면 명시 끝점·부모를 추가한다. 머리와 몸통을 움직이면서 팔·허리·다리 움직임도 섞어 본다. 목·허리·팔꿈치·손목·손가락·골반·무릎·발목의 굽힘/회전, 자세 사이 연속 이동도 검사한다. 자연스러운 옷 접촉을 모두 벌려 없애는 것을 목표로 하지 않는다.
5. **Unity PC 통합.** Humanoid 매핑과 T-pose, 보조본 제약, 실제 blendshape 구동, 분리 renderer 경로, 물리와 충돌을 구성한다. Blender/Unity에서 같은 입력을 주고 정점·본·키를 대조한다. 임의 런타임 C# 없이 필요한 동작이 가능한지 검사하고, 검사 전용 도구와 최종 프리팹을 분리한다. 클라이언트 테스트는 수행하지 않는다.

검증은 면적 경고(기본 대비 0.2 미만/3 초과), 선 길이/압축, 새 교차와 원래 접촉, 국소 실루엣·두께, UV/노멀 이음, 정지 원형, 변경 밖 좌표를 함께 본다. 면적 비 하나로 품질 판정을 하지 않는다. 동일 자세·카메라의 정면/측면/후면/높은 각도와 클레이·텍스처 비교를 남긴다. 랜덤 자세는 정규 자세와 중복 합산하지 않고 입력/seed를 기록한다.

반복 실패 시 그 결과를 버리지 않고 원래 면 ID, 본 입력, 보정 값, 그림을 기록한다. 관련 문서·소스에서 원인에 맞는 대안을 찾아 하나씩 변경한다. 개선과 회귀가 공존하면 총 경고 수만 보고 채택하지 않는다. 최종 문서에는 완료, 개선됐지만 잔여, 검증만 완료, 미완료를 구분한다.
