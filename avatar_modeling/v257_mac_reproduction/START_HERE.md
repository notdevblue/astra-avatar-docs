# v257 — Mac에서 인계 패키지와 실제 자세 재현

2026-09-12. 사용자가 Mac에서 미해결 문제 수정을 재개하도록 요청했다. 이전의 v256 중단 지시는 이번 재개 요청으로 대체됐다. **이 단계는 환경과 재현 검증 완료이며 아바타 관절 문제 해결 완료가 아니다.**

기존 `unity_vrchat_avatar`의 Unity 2022.3.22f1 / Windows x86_64 / SDK 3.10.5를 사용했다. lilToon 2.3.4를 [제작자 공식 배포](https://github.com/lilxyzw/lilToon/releases/tag/2.3.4)에서 설치하고 GitHub 릴리스의 SHA-256과 다운로드 파일 일치를 확인했다. 기존 기준본과 독립 후보 6개의 메시 지문·본 목록·Humanoid·재질·셰이더·누락 스크립트를 Windows 패키지 manifest와 대조해 모두 통과했다.

| 검사 | Mac 결과 | Windows와의 차이 |
|---|---|---|
| v255 실제 골반·무릎 51자세 | 모든 자세 이름과 압축 경고 목록 일치 | 보정 키 값 차이 0, 본 위치 최대 0.000147mm |
| 골반 각도 보고 | 지시한 실제 방향 재현 | 최대 0.027977도; 거의 곧은 무릎의 acos 수치 민감도 포함 |
| v256 노멀 239자세 | 같은 위치의 노멀 변경 재현 | 자세별 평균 노멀 오차 지표 차이 최대 0.000051도 |
| v256 새 200자세 평균 목표 오차 | 10.692323 → 10.412290도 | Windows 결과와 동일한 결론 |

노멀 변경 전후 위치 차이 최대 0.000302mm, 노멀 수식 재구성 최대 오차 0.000024도. 미세 수치 차이를 정확히 0이라고 쓰지 않는다. Mac의 프레임별 데이터·재생 보고서는 `.venv/mac_replay`, `.venv/calibrated_hips_255`, `.venv/coat_normal_runtime_256`에 분리했다. Git의 Windows 검증 결과는 덮어쓰지 않았다.

기존 v256의 오른팔 60도 노멀 회귀와 v253 기하 문제, v251 골반 문제는 재현되었으며 이 단계에서 수정하지 않았다. 후속은 v258의 노멀 회귀 제한, v259의 구매 레퍼런스 실제 각도 비교, v260의 기존 코트 천 시뮬레이션 목표 비교다. 각 후속의 실험/검증/채택 여부는 별도 기록을 따른다.

Unity 창을 UI 도구에서 찾지 못하는 경우가 있어, 열린 해당 프로젝트 안의 Editor 전용 파일 명령 도구로 검사했다. 첫 노멀 실행 요청은 스크립트 재컴파일 전 도착해 실패했고, AssetDatabase 갱신 뒤 실행했다. SDK 실행 자체 실패와 구분한다. 도구는 모델 로컬 가져오기·상태·검사 메서드 호출만 사용했으며 VRChat 로그인·빌드·업로드·클라이언트 실행은 없었다.

근거: `IMPORT_VERIFY.json`, `HIPS_COMPARE.json`, `NORMALS_COMPARE.json`, `NORMALS_RUNTIME_SUMMARY.json`, `LILTOON_INSTALL.json`. 구매 모델 원본 및 추출 자료는 공개 문서 공유 대상이 아니다.

후속 손 재현도 완료했다. Mac의 실제1,275자세에서 이전1,039의 압축15→0, 새200의6→0, SDK표본36 새압축0으로 Windows와 같은 결과다. 프레임 위치 재구성 최대0.000440mm, 노멀 재구성0.000033도 미만. 근거는 HANDS_SUMMARY.json이며, 접촉 문제까지 해결됐다는 뜻은 아니다. 사용자의 최신 방향은 v263부터 기본 변형의 근본 원인 추적이며 노멀만 개선해 완성으로 취급하지 않는다.
