# v353 레퍼런스 아트 방향과 검수 기준

이번 작업은 일본 애니메이션·게임·일러스트의 NPR 캐릭터를 목표로 한다. 사용자가 추가한 두 레퍼런스의 스타일을 존중한다. 최종 판정은 Unity 게임/PC VRChat에서 조명과 자세가 달라져도 정상적으로 동작하며 아름답게 보이는가이다.

머리 길이나 레퍼런스별 인상 차이를 이유로 기존 모델의 얼굴·실루엣을 재설계하지 않는다. 차분한 회갈색 정장, 밝은 셔츠, 짙은 넥타이, 부드러운 피부색의 관계를 유지한다. 머리의 컬 덩어리와 가는 가닥 선, 절제된 하이라이트, 또렷한 눈꺼풀과 눈동자, 옷깃·봉제선·접힌 면·단추·신발 구조가 읽혀야 한다. 사진 같은 섬유 노이즈와 광택을 임의로 추가하지 않는다.

## 새 텍스처의 기준

- 기존 아바타 텍스처 픽셀을 새 그림의 원본으로 사용하지 않는다. 원본은 비교와 오류 진단에만 보존한다.
- 레퍼런스에서 의도한 선과 디자인 색 변화는 유지한다. 넓은 방향성 그림자를 기본색에 고정해 겨드랑이·팔 안쪽·다리·코트 안쪽에 붙어 다니게 하지 않는다.
- 그림자를 줄인다는 이유로 단색 실루엣 수준으로 디테일을 지우지 않는다. 반대로 선명도를 높인다는 이유로 모든 삼각형이나 가닥에 검은 선을 넣지 않는다.
- 생성된 참고 채색은 모델 적용 결과가 아니다. 실제 UV에 베이크하고 모델에서 정면·측면·뒤·가린 영역을 직접 확인해야 한다.
- 두 장식이 겹쳐 보이거나 넥타이·코트 윤곽이 다른 옷에 인쇄되는 전사 오류는 미채택이다. 이미지 생성 시 위치 보존 지시를 했다는 사실은 정합 검증을 대신하지 않는다.

## 공식 자료와 제작 판단

lilToon은 그림자 강도·경계·흐림과 노멀의 그림자 기여를 분리한다. 경계를 선명하게 하거나 부분적으로 완화하여 애니메이션/일러스트 표현을 조절할 수 있다. 따라서 새 기본색과 선을 만든 후 큰 명암을 동적 셰이더로 분담한다. 이는 모든 부위에 똑같은 값을 쓰라는 뜻은 아니다. [lilToon 그림자](https://lilxyzw.github.io/lilToon/ja_JP/color/shadow.html)

노멀맵은 요철에 따른 조명 반응을 바꾸는 수단이며 선·홍채·단추 디자인 자체를 대신하지 않는다. 그려진 어두운 색을 일괄 높이로 바꾸면 색과 그림자를 홈으로 잘못 해석하므로 사용하지 않는다. 필요한 실제 미세 구조만 별도 베이크 후보로 비교한다. [lilToon 노멀](https://lilxyzw.github.io/lilToon/ja_JP/reflections/normal.html), [Unity 2022.3 노멀 임포트](https://docs.unity3d.com/ja/2022.3/Manual/texture-type-normal-map.html)

Unity Toon Shader도 기본색과 음영색을 분리해 표현한다. NPR에서 명암 설계는 가능하지만, 기본색에 이미 들어간 큰 얼룩이 광원 변경에 맞춰 사라지는 것은 아니다. 색만 표시한 진단과 실제 툰 조명을 함께 비교한다. [Unity Toon 기본 설정](https://docs.unity3d.com/ja/Packages/com.unity.toonshader@0.8/manual/Basic.html)

SiuSiu는 넓은 색면과 작은 선/광택의 분리를 참고한다. Bianca 레퍼런스와 의상/형태가 다르므로 해당 모델의 광택·얼굴 색을 그대로 복사하지 않는다. 기존 실제 비교는 avatar_shader/v002 및 v005 보고서에 있으며, 이번 신규 채색의 검증을 대신하지 않는다.

## 현재 진행 상태

새 기본색 8종과 여러 부위별 세부 채색, 눈 깊이·중복 면 정리, 헤어 UV·의복 전사·Unity 재질·물리 후보를 실제 제작·검토 중이다. 단추의 공통 투영과 바지 외곽 배경 혼입 수정은 실제 적용 사진에서 개선됐으나, 눈 바깥벽·머리 컬 방향·의복과 넥타이/헤어 접촉 등은 진행 중이다. [사진 포함 실행 기록](v353_WORK_REVIEW.md)에 시험별 근거·미채택 이유·독립 검토와 남은 작업을 구분했다. 생성된 원화나 실험 파일 존재를 최종 완료로 해석하지 않는다.

Blender는 Computer Use로 조작한다. Unity 지원 물리·콜라이더와 실제 SDK 갱신 후 메시/접촉을 검사하며, 정적인 포즈 사진을 중력·움직임 검증으로 대신하지 않는다. PC VRChat 클라이언트 검수와 Unity Editor 검수는 구분한다.
