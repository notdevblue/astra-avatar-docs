# v353 최신 V19 표면 + PAD1 넥타이 독립 검토

검토일: 2026-09-14. 제작자가 아닌 integration_audit 에이전트의 읽기 전용 재계산이다. 실제 Unity 실행·자산 수정·Blender 조작은 하지 않았다. 아래 판정은 `surface19_tie_detail` 실행에 한정한다. 뒤이어 실행되는 강한 정지 기울임·7종 이동/바람 검사와 합산하지 않는다.

## 판정

**최신 통합본의 이번 Bend 표면 표본에서는 넥타이–셔츠 교차가 BASE 26쌍에서 PAD1 0쌍으로 개선됐다는 주장이 재현된다.** 정확한 원래 삼각형 대응으로 42개 저장 표면을 캐시 없이 다시 계산했다. 결과는 기존 접촉 JSON의 모든 삼각형 쌍과 일치하며 최대 선분 길이 오차는 1e-9mm 미만이다.

이 수치는 관통 깊이가 아니라 교차 선분의 길이다. 기존 가중 지지 비교 실행의 **16쌍 / 10.3039mm**와 이번 같은 최신 표면·기존 물리 BASE의 **26쌍 / 10.6527mm**는 입력 프리팹이 다르다. 새 공개 보고서의 두 절은 이를 구분하고 있다.

## 실제 메시 대응과 보존

- BodyHair는 33,752정점, 원래 27,950삼각형에서 현재 27,850삼각형이다. 제거된 정확한 정점 삼중항 100개가 눈 정리 기록 `removed_unity_triangles[].unity_indices`와 일치한다. 제거 범주 전부 face이고 헤어 삭제는 0이다.
- Coat는 3,894정점·3,413삼각형 그대로다. 남은 모든 삼각형은 원래 인덱스와 유일하게 대응한다. 정점 집합뿐 아니라 원래 삼각형의 순환 방향도 별도로 확인했다.
- BASE/PAD1 양쪽 SOURCE JSON의 positions, triangles, weights, bones 배열은 두 메시 모두 정확히 동일하다. 본 배열은 129개다.
- 통합 빌드 JSON은 메시·UV·키·웨이트·재질 참조 보존, 실제 저장·재로드 중립 표면 차이 0mm를 기록한다. 이는 빌드 도구의 실제 검증 기록이며, 본 독립 재계산이 UV·셰이프키 전체를 Unity에서 새로 덤프한 것은 아니다.
- 셔츠 지지점은 원래 삼각형 25091→현재24991, 25511→25411에 정확 대응한다. 실제 정점 순서·중립 좌표·가중 지지 확인을 통과한 기록이 있다. 임의로 모든 인덱스를 100씩 이동한 대응은 아니다.

## 넥타이 밖 움직임의 작은 차이

정적 원본 배열 보존을 동적 비대상 차이 0으로 확대하면 안 된다. 21개 저장 표면을 같은 프레임끼리 대조하면 얼굴·손·셔츠·바지·신발은 0mm지만, 기존 헤어는 최대 **0.130075mm**, 코트는 최대 **0.00006144mm** 차이가 있다.

헤어 최대 표본은 Bend120의 Unity 정점 **16238 / 16247**이다. 같은 위치에 나뉜 두 정점은 같은 양만큼 움직이므로 이 두 점의 틈 벌어짐은 아니다. BASE 세계 좌표는 `(0.07352759, 0.86589295, -0.08338089)m`이며 기존 `hair_02_01` 40.17%, `head` 30.00%, `hair_01_01` 16.60%, `hair_02_02` 13.23%의 오른쪽 뒤 헤어다. 이 부위는 넥타이 지지점도 셔츠도 아니다.

600개 동작 행과 기록된 마지막 30개 warmup 행을 양쪽 실행에서 대조했다.

- phase/frame/active 입력, root 위치, 모든 hair_anchor/hair_wind 위치·로컬 회전, 공통 collider의 위치·회전은 동일하다. 기록된 deltaTime은 전 행에서 1/60초다.
- warmup와 중립 시작의 헤어 본 차이는 약 0.000002mm에 불과하다. 동작 17프레임부터 0.001mm를 넘고 동작 중 여러 기존 하부 헤어 체인이 함께 달라진다. 300프레임 이후에는 초기 수준으로 복귀한다.
- 모든 600프레임의 본 위치 중 최대 차이는 frame62 `hair_tip_00`의 **0.344140mm**다. 이는 본 끝의 위치 차이이며 메시 정점의 최대값 0.130075mm와 서로 다른 측정이다. 메시 정점은 21시점만 저장되어 전체 연속 최대를 증명하지 않는다.
- 두 실행의 실제 unscaledDeltaTime과 절대 fixedTime은 다르다. 예를 들어 frame120의 fixedTime은 3.52초 / 15.0199995초다. 그러나 어떤 시간값·내부 단계가 SDK 계산에 사용됐는지 원시 로그가 없으므로 이를 직접 원인으로 단정하지 않는다.

따라서 이번 로그는 **소스 메시 변경, 가시적인 지지점 입력 차이, 초기 warmup 미완료**를 원인으로 지지하지 않는다. SDK의 동적 계산 순서·내부 시간/상태 차이 가능성은 남는다. 넥타이 수정의 헤어 회귀인지 실행 간 변동인지 확정하려면 동일 BASE 재실행과 PAD1 반복을 같은 조건에서 비교해야 한다. 본 원시 행렬·SDK 내부 단계가 없는 현 자료만으로 정확한 스킨 분해나 무회귀를 선언하지 않는다.

## 접촉 분석기의 캐시 문제와 보완

최초 검토 당시 per-frame JSON이 있으면 입력 파일 해시 확인 없이 재사용했다. 삼각형 대응 코드만 수정해도 과거 결과가 그대로 남을 수 있는 재현성 결함이었다. 이번 독립 검토는 그 캐시를 읽어 계산하는 대신 실제 bin을 모두 다시 계산했으므로 현재 42표본의 수치는 별도로 확인됐다.

제작자가 수정한 현재 분석기는 양쪽 bin, 실제 SOURCE JSON, 눈 삭제 기록, 삼각형 대응의 원본 의존 파일, 분석기와 교차 도우미 코드 SHA를 provenance로 묶고, 정확히 같을 때만 캐시를 사용한다. Cloth 입력이 있으면 해당 source/실제 particle 기록도 포함한다. 수정된 코드의 조건을 읽어 확인했다. 재실행 후 42개 결과 파일 모두의 입력 파일·분석기·도우미 SHA를 현재 디스크 파일에서 다시 계산하여 provenance와 일치함을 확인했다. 불일치 0이다.

## 완료 범위와 보고서 보완

실제 RUN은 BASE/PAD1 각 600프레임 완료, 오류 없음, SDK `OnFrameCompleteLate`, warmup90, 명시적 canonical 중립 통과를 기록한다. 원래 장면 복원도 equal=true다. 다만 다음 한계는 유지한다.

1. 교차 표본은 각 `0,29,30,60,…,570`의 21시점이다. 30fps 연속 영상과 60Hz 본 로그가 있다는 사실만으로 매 프레임 표면 교차를 검사한 것은 아니다. 최종599 프레임 표면도 이 실행에서는 저장하지 않았다.
2. 범위는 tie 양의 웨이트를 갖는 삼각형188개 대 셔츠1125개, 넥타이–코트3413개, 코트–바지1724개다. 같은 중립 위치를 공유하는 tie–shirt 정점 쌍은 제외한다. 전신 자기 교차·연속 swept 검사·모든 공면 접촉 검사가 아니다.
3. 실제 Bend는 흉부 ±15도 입력이다. 강한 정지 기울임, 모든 이동·회전·바람, 머리–코트·어깨의 전수 무회귀 및 PC VRChat 클라이언트 검증을 대신하지 않는다.
4. 통합 JSON의 “후속 실행 필요” status는 빌드 시점 기록이다. 현재 별도 Bend 실행은 완료됐으므로 모든 동작을 미실행으로 해석하지 않는다. 반대로 강한 정지 기울임/전체 동작 완료로 확대하지 않는다.
5. 주 보고서 6절의 “새 후속 독립 검토는 수행되지 않았다” 문구는 본 검토 이후 갱신해야 한다. 이번 독립 범위는 최신 V19 접촉42표본·정확한 삼각형 대응·본 로그 공정성이다. 영상 전체의 독립 시각 검수나 어깨540/Cloth 전수 독립 재계산을 수행했다는 뜻이 아니다.

이 문서에서는 새 영상을 독립적으로 전부 시청했다고 주장하지 않는다. 제작자의 실제 디코드·원본 사진 검수 기록과 본 수치 검토를 구분한다.
