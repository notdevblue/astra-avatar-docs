# v353 코트 하부–전완 소매 충돌 분리 후보

V1은 자락–소매의 새 교차184쌍 때문에 미채택이다. 다음 후보는 V1의 낮은 구간 힘 분배를 유지하고 전완 소매를 따라 움직이는 캡슐 두 개만 코트 충돌 목록에 더한다. 코트/소매 형상, UV, 재질, 노멀, 본 rest, 웨이트, 사용자 승인 무릎·손가락은 바꾸지 않는다.

## 실제 자료로 정한 범위

| 대상 | 자료 | 최소 캡슐 후보 |
|---|---|---|
| 왼 전완 소매 | V1 신규 접촉의 forearm 우세44정점 | 반경35 mm, 전체 높이134.290 mm |
| 오른 전완 소매 | 같은 기준43정점 | 반경32.5 mm, 전체 높이130.693 mm |

원래 메시 좌표와 해당 본 inverse bind를 이용해 전완 로컬 Y축 기준으로 맞췄다. 각 본의 균일 scale100을 반영한 로컬 수치이며, 캡슐은 기존 forearm의 직접 자식 Transform에 둔다. PhysBone root를 팔 본으로 바꾸지 않는다. 새 표면 지지본·새 메시·웨이트 수정은 없다. 현재 영향을 받는 코트4체인의 목록에만 추가하며 헤어·넥타이 목록은 보존한다.

VRChat 공식 설명상 캡슐의 Height는 Y축 양끝 반구를 포함한 전체 길이이며, Global Collision=False이면 명시적으로 연결한 PhysBone에만 작용한다. 따라서 일반 Transform 부모 추종과 코트 목록 한정이 이 후보의 구현이다. [공식 PhysBone Collider 문서](https://creators.vrchat.com/common-components/physbones/#vrcphysbonecollider)

## 현재 실행 상태

V2 첫 Build는 `PB force/profile changed` 검증에서 중단됐다. 저장 전 실패로 후보 prefab과 성공 보고서는 아직 생성되지 않았다. 이는 실제 물리 결과가 아니다. 뒤이은 실제 진단에서4개 코트 PB의 변화는 `MonoBehaviour.colliders` 배열6→8뿐이며, 다른 모든 직렬화 필드는 같았다. V2의 최상위 `Remove("colliders")`가 false로 반환돼 실제 목록을 제거하지 못했던 검증 코드 오류다. 별도 V3 helper에서 확인된 정확 경로만 제외하고 serialized/live 목록 길이 일치, 다른 필드 정확 보존, before/after 원문 기록을 유지했다. 물리 후보의 설정과 출력 이름은 V2 그대로이며 재실행 결과는 아직 대기 중이다.

## 적용 전에 확인할 관문

- 원본 V1의 의존성 hash 및 메시 전체 배열/본 rest/키/UV가 같아야 한다.
- source 본 로컬 캡슐 맞춤과 실제 native rest 표면 관계를 확인한다. 선택 소매 점이 캡슐 밖으로1 mm를 초과하면 Build를 중단한다.
- 각 코트 체인과 새 캡슐의 최초 간섭 여유를201개 표본으로 검사한다. 최소0.5 mm 미만이면 Build를 중단한다. 이 표본은 연속 완전충돌 판정이 아니다.
- 다른 PB 필드, 원래 목록, 다른 헤어·넥타이 설정을 정확 보존하고 reload 후 다시 검증한다.

## 실제 검수 계획

별도 Play의 첫 순서로 같은1,800프레임을 실행한다. 원래 source19와 V1을 각각 비교해 상부 몸판·01전이·02자락·소매별 변위를 분리한다.66개 실제 스킨 표면에 대해 코트 전체 자기 교차, 코트–바지, 넥타이–셔츠/코트를 검사한다. 새 소매 대리 캡슐은 각 표본의 실제 SDK 위치·회전·scale로 재구성하고, 원래 접촉 소매87정점의 실제 스킨 표면을 얼마나 덮는지 확인한다. 단순히 팔 본의 자식이라는 이유만으로 정확한 소매 표면 추종이라고 단정하지 않는다.

좌·우·앞 held299의 정면/양측면 확대도 비교한다. 저장한 실제 SDK 기하를 다시 그리는 사진은 `STATIC_BAKED / ALBEDO`로 표시하고, 실시간 물리 영상 또는 실제 셰이더 검수와 구분한다. 같은 자세 전후는 원래 몸판 bounds로 카메라를 고정한다.

새 캡슐이 교차를 줄이더라도 과한 자락 벌어짐, 상부 지지 변화, 새로운 몸/소매 접촉 또는 복귀 문제를 만들면 채택하지 않는다. 기존 틸트3종 표본이 전체동작/PC 클라이언트 합격은 아니다.
