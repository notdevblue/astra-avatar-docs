# v353 눈꺼풀 복원 실행·미채택 기록

## face8 첫 후보

긴 눈꺼풀 접힘선의 농도·폭·위치를 보강하고 짧은 안쪽 보조선을 추가했다. 아래눈꺼풀과 주속눈썹도 보강했다. Blender의 실제 베이크와 별도 사본 저장·재열기에서 기존 형상/UV/노멀/본/웨이트/키 보존을 확인했다.

Unity 실제 0/35/55도 × 근접/중거리 전후12장을 직접·독립 검수했다. 정면에서 눈꺼풀이 읽히는 개선이 있었지만 사선에서는 긴 선의 외측 계단과 주속눈썹 위의 가는 잔선이 새로 생겼다. **face8은 미채택**이다. 파일 저장·원형 보존과 미관 채택은 다르다.

## face9 두 번째 후보

face7에서 매끈하게 보이던 긴 접힘선 좌표를 유지하고 농도·폭만 보강한다. 짧은 안쪽 보조선과 약한 아래눈꺼풀 보강은 유지한다. face8에서 확대한 주속눈썹 폭은 face7로 되돌렸다. 별도 텍스처·Blender 사본으로 저장했으며 원본 Hair29를 수정하지 않았다.

사선 잔선의 직접 원인은 아직 면별 UV/깊이 기여까지 분리 확정하지 않았다. 문제를 보인 위치·폭 변경을 되돌리고 실제 전후 재검수로 판단한다. 구조 전체를 새로 만들거나 기존 눈꺼풀 면을 삭제하는 방법은 사용하지 않았다.

## 실행 중 발견한 검증 문제

- Blender 파일을 열면 이전 콘솔 입력줄이 복원되어 다음 명령과 붙는 경우가 있었다. SyntaxError가 난 시도는 저장 성공으로 세지 않았고, 빈 입력줄에서 재실행했다. 별도 저장/재열기 증거로 확인했다.
- Unity V1은 재질 이름을 비교에서 제외하면서 문자열의 하위 문자 배열까지는 제외하지 않아 거짓 실패가 발생했다. 실제 YAML 차이는 이름과 얼굴 MainTex 참조뿐이었다. V2에서 이름 하위 순회만 수정했고 실제 원본/장면/재질 보존과 사본 재로드를 통과했다.
- face9용 V3 준비 때 변수명은 face9였으나 입력 파일명 두 곳이 face8로 남았다. 실제 SHA 검사에서 생성 전 차단됐다. V4는 파일명과 증거 출력 버전을 수정했다. 잘못된 입력을 허용하도록 검사를 느슨하게 만들지 않았다.
- Unity의 재컴파일·어셈블리 재로드 중 대기 도구가 시간 초과한 것은 작업 취소가 아니었다. 같은 작업을 중복 실행하지 않고 실제 완료 JSON을 확인했다.

최종 미관 판정과 사진은 루트 복원 보고서에서 확인한다. 위의 기술적 통과만으로 최종 얼굴·표정·VRChat 품질을 주장하지 않는다.
