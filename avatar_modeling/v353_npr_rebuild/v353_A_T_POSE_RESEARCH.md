# v353 A/T 기본 포즈 검토 — 조사 및 비교 착수

사용자 추가 지시(2026-09-14): 현재 A 포즈 대신 T 포즈를 기본으로 사용할 때 텍스처 늘어짐과 토폴로지 문제에 도움이 되는지 검토한다. 기존 제작·Unity 검증은 계속하며, 포즈 변경을 자동 채택하지 않는다.

## 구분할 세 가지

| 경우 | 실제 변경 | 이번 비교의 의미 |
|---|---|---|
| 현재 A 바인드 + T 자세 | 팔 본 회전, 스킨 결과 | T 자세에서 면과 UV 밀도의 변형 확인 |
| Unity Humanoid T 기준 | Avatar 매핑/캘리브레이션 | 모델의 바인드 포즈 변경과 별개로 리타게팅 기준 확인 |
| 진짜 T 바인드로 재설정 | 메시 기준 좌표와 bind matrix, 보정 키/노멀/애니메이션 기준 재전사 | 동일 목표 자세에서 실제 신장·압축·부피가 나아지는지 확인 |

Unity는 Humanoid Avatar의 올바른 T 포즈 매핑을 요구하며 Sample Bind-pose와 Enforce T-Pose를 별도 기능으로 제공한다. 따라서 화면의 A 포즈만으로 Humanoid 기준이 잘못됐다고 판단하지 않는다. [Unity 2022.3 Humanoid 설정](https://docs.unity3d.com/2022.3/Documentation/Manual/ConfiguringtheAvatar.html)

각 본의 bind pose는 바인드 시점 변환의 역행렬에 관련된 스키닝 기준이다. 본을 T자로 보이는 것과 스키닝 기준을 다시 만드는 것은 다르다. [Unity Mesh.bindposes](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Mesh-bindposes.html)

Blender의 Pose as Rest Pose는 armature의 기본 상태를 바꾸며, 기존 스키닝·제약·드라이버·애니메이션·내보내기 자산의 재조정이 필요할 수 있다. 기존 32개 코트 보정과 새 어깨/Ribbon 보정을 버리고 기본 포즈만 바꾸는 방식은 비교 후보로 채택하지 않는다. [Blender Apply](https://docs.blender.org/manual/nl/5.2/animation/armatures/posing/editing/apply.html)

## 실측 계획과 완료 조건

1. 현재 실제 본/메시 bind matrix에서 휴지 팔 각도와 Unity T 캘리브레이션을 각각 확인한다.
2. 같은 팔 내림·45°·90°·150° 목표에서 겨드랑이/어깨/소매의 같은 삼각형 UV→표면 Jacobian, 면적, 국소 두께를 비교한다.
3. 포즈만 바꾼 경우 UV 좌표와 연결은 그대로이므로, 차트 오류 수정과 스킨 변형에 의한 신장을 분리한다. 이것은 구조적 판단이며 실제 개선 수치를 대신하지 않는다.
4. T 바인드 사본이 필요하면 기존 메시와 모든 보정 키/N/T/바인드행렬을 전사하고 원형으로 왕복했을 때 오차를 확인한다. 새 메시 재생성은 하지 않는다.
5. 같은 세계 좌표의 동작을 비교한다. A·T의 서로 다른 로컬 회전 수치만 비교해 T가 더 좋다고 결론 내리지 않는다. 팔을 내린 상태의 새 압축도 함께 평가한다.
6. 최종 판단은 Unity에서 같은 재질·조명·카메라와 실제 구동으로 수행한다. 효과가 없으면 근거와 미채택 사유를 기록한다.

현재 상태: 공식 문서 조사 완료, 읽기 전용 실측 준비 중. T 바인드 적용이나 시각 품질 개선을 아직 주장하지 않는다.


## 1차 실제 스킨 실측과 재바인드 수학 비교

현재 원래 바인드에서 위팔은 아래 방향 기준 양쪽 **20.7135°**, 팔꿈치는 **9.2219°** 굽혀져 있다. 흔히 말하는 45° A 포즈와도 다르다. Humanoid 캘리브레이션과 실제 메시 바인드는 따로 확인해야 한다.

기존 실제 SDK 시험에 저장된 같은 어깨 335삼각형을 비교했다. 아래는 **저장된 실제 스킨 좌표**의 결과다. UV 좌표·삼각형 연결은 세 자세 모두 동일하다.

| 실제 자세 | UV→표면 방향별 비율 P95 | 원래 바인드 대비 최대방향 신장 P95 |
|---|---:|---:|
| A 중립 20.6885° | 1.61165 | 1.08281배 |
| T 90° | 1.77565 | 1.36454배 |
| 팔 올림 149.8458° | 3.38116 | 1.49555배 |

P95는 같은 영역의 면적 가중 백분위다. UV→표면 비율은 두 특이값의 비율이며, 텍스처 해상도나 미관 점수와 같지 않다. 현재 팔을 T로 올리기만 하면 기존 삼각형의 방향별 늘어짐이 자동으로 줄지는 않는다. T를 새 분모로 쓰면 T에서 신장이 1이 되는 것은 정의상 결과이며 실제 개선 근거가 아니다.

추가로, 원래 웨이트를 유지한 채 T의 스킨 좌표와 새 역바인드 행렬을 사용하는 **오프라인 선형 스키닝 수학 사본**을 계산했다. 실제 세계 본 행렬을 동일하게 놓아도 A 복귀에서 같은 어깨 315점 중 최대 **8.50416mm**, 150°에서 **7.38145mm** 달라졌다. 위팔 시작 1/4에 해당하는 고정 선택점의 정면 방향 폭은 A에서 약 57.50mm가 수학 사본에서 48.82/49.56mm가 되었다. 이는 같은 점 집합의 투영 폭이며, 닫힌 단면 두께나 전체 부피가 아니다.

따라서 **단순 T 재바인드를 원형 보존 수정안으로 채택하지 않는다.** T를 기준으로 새로 적절하게 웨이트를 조정한 모델까지 시험한 결과는 아니다. 보정 키 및 N/T 역전사, Humanoid 재조정과 실제 자산 저장도 이 수학 사본에서는 수행하지 않았다.

## 사진 시점 검수에서 발견한 제한과 추가 실행

기존 ActiveSweep의 첫 기록(frame 0)은 본과 BakeMesh 좌표가 T 90°였지만, 같은 번호의 실제 PNG는 A 포즈였다. 직접 이미지 검수에서 발견했으며 **frame 0 PNG를 T 포즈의 시각 증거로 사용하지 않는다.** 이어지는 frame 3과 6에서는 팔이 올라온 모습이 확인된다. 현재 증거로는 첫 GPU 스킨 갱신 지연 가능성이 있으며, 전체 영상과 저장 스킨이 모두 동일 시점이라고 확정하지 않는다.

이 때문에 정확한 0°/45°/90°/150° 세계 위팔 방향을 각각 30프레임 유지한 뒤 마지막 프레임만 저장·촬영하는 별도 실제 SDK 도우미 (공유본 미포함: `MacV353ATPoseReadOnlyV1.cs`)를 준비했다. 원형 BASE와 V7 보정 후보를 비교하며 UV/웨이트/바인드 변경이나 새 키 수동 주입은 없다. **오프라인 컴파일만 완료했고 실제 추가 시험은 대기 중이다.** 기존 전신 시험에 T 90° 입력은 포함되어 있지만, 이 추가 시험은 정확 0°/45° 및 안정된 사진 대조를 보완한다.
