# v332 · 비앙카 셰이더 작업 계획

2026-09-12 · **계획만 작성. 아래 값은 아직 적용하거나 최종 검수한 preset이 아니다.** 실제 조사 근거와 비교 사진은 [v332 분석 보고서](v332_SHADER_REVIEW.md)에 있다.

## 목표와 작업 기준

비앙카의 얼굴 인상·갈색 정장·머릿결·신발 디테일을 유지하면서 SiuSiu처럼 **색면이 분명하고, 밝은 표현이 필요한 부위에만 들어가는 화면**을 목표로 한다. 머리와 천과 가죽이 모두 같은 반짝임을 갖지 않도록 한다.

기존 lilToon 2.3.4로 시작한다. 현재 프로젝트와 같은 Unity/색공간에서 비교하고, 셰이더 버전 변경을 동시에 진행하지 않는다. v324 Head/Paint 텍스처와 현재 검수 재질은 보존하며, 후속 작업의 별도 버전 폴더에 재질 사본·전용 마스크·검수 프리팹을 둔다. v324를 재질 출처로 쓴다는 이유로 v330 또는 다른 리그 후보를 합치거나 형상을 자동 변경하지 않는다.

새 메시/대체 모델/리메시/새 본은 필요하지 않다. 최초 후보에서는 위치·면 연결·UV·노멀·웨이트·보정키를 전부 유지한다. SiuSiu의 MatCap·마스크·재질 파일을 비앙카 패키지에 복사하지 않고, 비앙카 그림과 UV에 맞춘 자료를 새로 만든다.

## 1단계 — 비교 기준과 영역 마스크부터 고정

후속 폴더에 `Materials/`, `Masks/`, `MatCaps/`, `Review/`를 만들고, 기존 재질4개를 사본으로 분리한다. 공유 대상은 보고서·비교 렌더이며 제작 텍스처와 내부 자료는 작업 저장소에 보존한다.

가장 먼저 현재 MainTex 위에서 얼굴/눈/머리/피부/셔츠/정장/넥타이/신발·장식의 위치를 확인한다. v324 표면 분류와 UV를 출발점으로 쓰되 마스크 경계를 실제 모델 위에서 다시 검수한다. 섬 밖 여백·mipmap 축소에서도 다른 부위로 효과가 새지 않아야 한다.

| 새로 만들 자료 | 목적 | 첫 크기 제안 |
|---|---|---|
| Head 그림자 강도 마스크 | 얼굴의 과한 동적 음영 억제, 눈/입 디테일 보호 | 1024² |
| Head MatCap1 마스크 | 필요한 피부/머리 영역의 아주 약한 곱셈 음영 | 1024² |
| Head MatCap2 마스크 | 머리 하이라이트만 허용, 얼굴·눈에는0 | 1024² |
| Paint 그림자/MatCap 마스크 | 피부·흰 셔츠 보호, 천/신발/장식 구분 | 효과별512–1024² |
| 비앙카용 MatCap1 | 넓고 완만한 음영. 초기에는 중립에 가까운 색 | 256² |
| 비앙카용 MatCap2 | 부드러운 좁은 밝은 띠. 흰 테두리의 과다 발생 억제 | 256² |

각 효과 입력에 맞는 독립 마스크를 사용한다. 여러 부위를 RGB에 넣었다는 이유만으로 lilToon이 원하는 부위를 자동 선택한다고 가정하지 않는다. 초기 강도 마스크는 회색조/선형 데이터로 설계하고 sRGB OFF에서 읽히는 값을 확인한다. [Unity 선형 텍스처 문서](https://docs.unity3d.com/2022.3/Documentation/Manual/LinearRendering-LinearTextures.html) 색을 담은 MainTex·MatCap은 sRGB 색 텍스처로 취급한다. 마스크/MatCap의 픽셀값·합성·중간값 테스트를 먼저 해서 색공간 오류를 스타일 차이로 오해하지 않는다.

**슬롯 증가는 첫 단계에서0을 목표**로 한다. Head 아틀라스 안의 얼굴과 머리는 같은 재질 설정을 공유하므로, 예를 들어 MatCap1은 얼굴 중심의 약한 음영, MatCap2는 머리만 밝히는 마스크로 역할을 나눌 수 있다. Paint에서도 피부와 천은 마스크로 우선 분리한다. 서로 다른 부위에 서로 다른 MatCap 그림/독립 파라미터가 꼭 필요해 두 층으로 부족할 때만 기존 면의 재질 슬롯 분할을 별도 검토하고 비용을 기록한다. 처음부터 메시를 나누지는 않는다.

## 2단계 — 얼굴 밝기와 그림자만 비교

다음 세 조건을 같은 프레임에서 나란히 본다.

1. A: 현재 설정 그대로.
2. B: 기존 툰 그림자 강도는 유지하되 얼굴 영역 마스크만 줄임.
3. C: B에 얼굴 영역의 약한 곱셈 MatCap을 추가.

입·코·눈 주변의 회색 얼룩이나 얼굴의 평평해짐 여부를 본다. 현재 얼굴 디테일을 뭉개는 베이스 텍스처 수정은 이 단계에 섞지 않는다. SiuSiu의 ‘Shadow 전체 OFF’를 정답으로 고정하지 않고, 비앙카의 목·옷과 연결이 자연스러운지 비교한다.

초기 얼굴 그림자 마스크는 현 상태100% 대비0/25/50% 통과의 세 조건으로 시험할 수 있다. MatCap1은 적용 마스크를 확정한 뒤 Blend0/0.15/0.30 정도의 작은 후보부터 비교한다. 이 값들은 **검수할 시작점**이며 이미지의 색과 마스크에 따라 실제 결과가 달라진다. 얼굴 전체 Emission은 추가하지 않는다.

## 3단계 — 머리에 좁고 약한 하이라이트

얼굴 후보를 고정한 뒤 머리 전용 MatCap2 마스크를 붙인다. 가산 Blend0/0.10/0.20의 작은 후보부터 비교하고, 기존 갈색 머릿결과 겹쳐 흰 띠가 생기면 강도 또는 마스크를 낮춘다. 넓은 앞머리 덩어리는 매끈하게 읽히되 모든 작은 홈이 번쩍이지 않게 한다.

SiuSiu의 머리 MatCap2처럼 가산에 조명 반영을 켜는 후보를 출발점으로 삼는다. 카메라를 옆으로 돌릴 때 띠가 얼굴로 새거나, 고개를 기울일 때 하이라이트가 크게 회전하면 Z회전 보정/시차/마스크를 함께 점검한다. 현재 UV를 유지한 채 시작하며 UV1 추가나 노멀 재계산은 기본 단계에 넣지 않는다.

앞머리가 한쪽 눈을 가리는 현재 인상은 유지한다. 스텐실은 마지막 선택 항목으로 남긴다.

## 4단계 — 천·가죽·장식의 반응 분리

| 부위 | 시작 방향 | 중단/재조정 신호 |
|---|---|---|
| 코트·바지 | 넓은 면의 약한 음영, 밝은 띠는 매우 제한 | 주름마다 흰 테두리, 검은 홈 증가, 가죽처럼 번들거림 |
| 셔츠 | 과한 회색 동적 그림자만 줄이고 원래 주름 보호 | 흰 면이 날아가 단추·깃/접힘 소실 |
| 넥타이 | 어두운 실루엣과 매듭 유지, 국소 약한 반응 | 주변 셔츠와 붙거나 매듭이 뭉개짐 |
| 신발·단추·금속 장식 | 해당 부위만 더 좁은 하이라이트 허용 | v324 복원 장식이 반사에 묻힘, 천까지 효과 번짐 |
| 피부·손 | 얼굴과 밝기 연결, 옷 효과에서 제외 | 손이 장갑처럼 광택을 띠거나 얼굴과 색 분리 |

천의 가산 MatCap Blend는0/0.05/0.10, 장식 후보는0/0.15/0.30부터 작게 비교한다. 동일 Paint 재질 안의 차이는 마스크 값으로 먼저 조절한다. 천과 장식에 아예 다른 하이라이트 그림이 필요하면 두 MatCap 층의 배분을 다시 설계하거나 추가 슬롯을 검토한다. **현재 슬롯에서 모든 부위를 무제한 독립 제어할 수 있다는 계획은 아니다.**

툰 그림자는0/0.25/현재0.5를 비교하되 색과 경계까지 한꺼번에 바꾸지 않는다. 소매·팔꿈치의 실제 실루엣 각짐은 셰이더로 해결됐다고 판정하지 않는다. 기존 허용 주름과 v330의 남은 교차 판정도 바꾸지 않는다.

## 5단계 — 그림에 남은 명암이 방해하는 경우에만 국소 조정

그림자 OFF에서도 검은 홈이나 강한 하이라이트가 남으면 BASE_ONLY 진단을 다시 본다. 필요하면 기존 디테일을 보존한 채 특정 넓은 명암만 완화하는 텍스처 사본을 비교한다. **v323처럼 전체를 평탄화한 뒤 디테일을 잃는 경로를 반복하지 않는다.**

이 분기는 셰이더와 텍스처를 동시에 바꿔 원인을 잃지 않도록 별도 후보/사진으로 기록한다. 얼굴 인상·헤어 실루엣·정장 비례를 바꾸는 작업으로 확대하지 않는다. 텍스처만으로 충분하지 않더라도 자동 메시 교체나 재생성으로 넘어가지 않는다.

## 6단계 — 선택 효과는 마지막에

- **눈 Emission:** 주광 OFF에서 눈만 지나치게 죽는 경우 작은 영역에 한해0/약한 후보 비교. 얼굴 전체 발광은 피한다.
- **Outline:** 첫 후보에는 추가하지 않는다. SiuSiu의 밝은 가장자리는 이번 분석에서 Outline이 아니었다. 나중에 필요하면 OFF/얇은 후보를 1m·3m·5m에서 비교한다.
- **Rim:** MatCap과 겹쳐 이중 흰 테두리가 생기지 않는지 확인할 수 있을 때만 선택적으로 시험한다.
- **스텐실:** 현재 앞머리 가림을 바꿔야 할 명확한 요청이 있을 때만 얼굴/눈 파츠·깊이·Queue·양안 표시를 조사한다.
- **NormalMap/Reflection:** 기본 마스크·MatCap만으로 목표가 충족되는지 먼저 판단하고 필요 부위만 후속 검토한다.

## 검수 장면과 통과 기준

한 장의 예쁜 정면 사진으로 채택하지 않는다. **같은 자세·각도·노출에서 현재/A/B/C 후보를 비교**하고 각 효과 OFF 사진도 함께 남긴다.

| 검수 | 확인할 것 |
|---|---|
| 정면·좌우45°·측면·뒤, 얼굴/상체/전신 | 얼굴 인상·색·디테일 유지, 새로운 밝은 줄·이음새 없음 |
| 정사영 비교 + 실제 사용에 가까운 원근/거리1·3·5m | 머리 띠 이동, 작은 마스크의 깜빡임·축소 손실 |
| 주광 정면·옆·뒤·OFF, 흰 강광·따뜻한 빛·차가운 빛 | 회색 얼굴·백색 날림·과한 자기발광·목/손 색 분리 |
| 실제 cast shadow ON/OFF, Light Probe 조건 변경 | 머리·코·옷의 그림자 관계, Renderer별 밝기 불일치 |
| 기본 자세·팔90°·깊은 굽힘·몸 회전, 연속 카메라 회전 | 하이라이트가 접힘을 과장하는지, 자세별 새 이상 |
| VRChat PC 거울·양안 VR·다른 월드·셰이더 차단 | MatCap 시차·투명/스텐실 표시, fallback 정상성 |
| SDK 통계 + 같은 PC의 GPU 측정 | 슬롯·텍스처 메모리·패스와 실제 부하의 증가량 |

현재 밝기 하한0.2/상한1, AsUnlit0.1은 시작 기준으로 고정한다. 기능과 마스크를 조절한 후 필요하면 하한0.1/0.2, AsUnlit0/0.1 정도만 분리 비교한다. 밝기를 무조건 올려 어두운 월드에서도 혼자 떠 보이는 결과를 합격으로 보지 않는다. PC용 VRChat이 대상이며 Android 대응은 이번 계획에 추가하지 않는다.

색 차이·마스크 경계·기존 디테일 보존 여부는 전후 사진으로 판단한다. `픽셀 차이0`를 스타일 개선 기준으로 삼지 않으며, 실측하지 않은 FPS·성능등급을 예측 완료값으로 기재하지 않는다. Mac Editor 확인과 실제 Windows/VRChat 검수도 구분한다.

첫 제작 범위로는 **기존4재질·2아틀라스 유지 + 비앙카 전용 마스크 + 약한 MatCap 두 층**이 적절하다. 결과를 보고 필요할 때만 텍스처 명암의 국소 수정이나 슬롯 분리를 추가한다. 이번 v332은 이 실행 순서를 문서화한 단계이며 실제 제작은 아직 진행하지 않았다.
