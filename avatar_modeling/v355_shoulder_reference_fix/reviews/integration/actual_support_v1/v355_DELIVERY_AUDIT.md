# v355 최종 전달 독립 감사

**전달 파일의 실물·해시·패키지 내용과 보고서의 검증 경계는 일치한다.** 사용자 외형 최종 승인 전의 Unity Editor 검수 전달본이라는 상태가 유지되어 있다. 원형 P1을 덮어쓰거나 V13을 자동 채택한 전달은 아니다.

## 파일과 패키지

- DELIVERY의4개 전달물과9개 근거 파일, 총13개 SHA256을 현재 파일에서 다시 읽어 모두 일치함을 확인했다.
- `.unitypackage` 압축을 읽어 실제28개 asset을 나열했다. 각 asset의 바이트 SHA는 UNITY_PACKAGE 목록 및 현재 Unity 프로젝트 파일과 모두 같다.28개 `asset.meta`도 현재 프로젝트와 바이트가 같다. 누락/목록 밖 자산0이다.
- 패키지 SHA는 `e9c42360bb25f643f16bf0778fa054e47cd25f24fc6383ba80ed645f628e419a`로 DELIVERY/UNITY_PACKAGE/PACKAGE_ARCHIVE_VERIFICATION과 일치한다.
- SDK와 lilToon의7개 외부 의존 경로는 별도로 선언되어 있고 패키지에 포함된28자산으로 잘못 세지 않았다. 새 프로젝트에서 가져오기 검증은 하지 않았다는 상태도 일치한다.
- 메인 보고서의 저장소 내 상대 링크는 모두 존재한다. 외부 웹 링크의 접속 상태를 새로 검사한 것은 아니다.

현재 Unity/Blender를 실행하거나 Assets를 수정하지 않았다. 상세 자산·메타 SHA는 `DELIVERY_AUDIT_EVIDENCE.json`에 기록했다.

노멀의 일반 범위는 저장기가 정규화한 방향 자료이며, 별도7자세 raw N/T probe가 정규화 전 길이를 확인했다는 순서가 올바르게 구분되어 있다. 원래 재질 사진을 다른 shader/outline/normalmap의 안전성으로 확대하지 않는다. 이 감사자가70장의 새 probe 사진을 전부 직접 확인했다는 주장은 없고, 해당 직접 검수는 참고 담당자의 기록에 귀속한다.

## 문구 보완 요청

메인 보고서의 ‘함몰 지표는 경로의 현에 대한 거리’는 실제 계산보다 모호하다. 수식은 XY투영에서 양끝점 연결선에 대한 **Y방향 최대 세로차**이므로, ‘XY투영 경로의 양 끝점을 잇는 선과의 최대 세로거리’로 두 곳을 보완하도록 부모에게 전달했다. 수치 오류는 아니며 이 문구 외 전달/완료 범위의 실질적 불일치는 발견하지 못했다.

게시 전후 파일이 다시 바뀌면 이 감사 시점의 SHA와 구분해야 한다. 이번 확인은 로컬 실물 및 검증 기록 감사이고 원격 main 게시 완료 검증은 부모 작업이다.
