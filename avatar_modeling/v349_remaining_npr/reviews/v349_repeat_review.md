# v349 콜라이더 0.3mm 후보 반복 기술 검토

## 판정

**검사한 실행 범위에서 0.3mm 후보의 원래 보호면 여유는 안정적으로 양수였다. 다만 본 움직임의 완전한 결정적 재현성은 확인되지 않았다.** 후보 3회 중 가장 작은 원래 Neck 보호면 여유는 +0.072134mm다. 이 결과를 전체 메시 접촉 0, 모든 속도·FPS 안전 또는 VRChat 클라이언트 합격으로 확대하지 않는다.

최종 padding 비교에는 현재 repeat의 **FinalRepeat ↔ OriginalRepeat**를 사용한다. 두 실행의 기록된 root 위치, collider 변환, anchor/wind 위치·회전이 일치하며, 영향 대상이 아닌 넥타이도 전 프레임 정확히 일치한다. 실행 순서상 첫 후보와 후속 후보 사이의 차이는 별도 반복 편차로 남긴다.

## 증거 및 검사 단위

- `avatar_modeling/v349_remaining_npr/physics/repeat/RUN.json`: error null, Final/FinalRepeat/OriginalRepeat 모두 완료, SDK `OnFrameCompleteLate` 이후 기록, 후보당 4,800 active frame, 실제 워밍업 90 frame 중 마지막 30개가 JSON에 기록됨.
- 앞선 `physics/Original_MOTION.json`, `physics/Final_MOTION.json`도 대조했다. 표의 FirstFinal은 앞선 Final 파일이며, Final은 이번 repeat 폴더의 첫 후보다.
- 각 실행 60Hz·80초, 7구간, Wind 입력 10초 + 자연 감쇠 10초. 강제 리셋 없이 마지막 복귀를 확인했다.
- 헤어 6체인의 `_02`와 `hair_tip` 총 12개 끝점에 반경 4mm 구를 적용했다. 2개 capsule × 12개 끝점 × 4,800 frame = **실행당 115,200개 끝점–콜라이더 거리 표본**이다. 두 capsule의 표본을 하나의 전신/표면 검사 개수로 부르지 않는다.
- 매 프레임 실제 world 중심, `rotation * local_rotation`의 Y축, 기록된 radius/height와 lossyscale를 사용했다. 원래 보호면 거리는 같은 해당 프레임 변환에서 **패딩 전 반경·높이**로 다시 계산했다. 전체 본 segment 및 스킨 표면 교차 검사가 아니다.
- 모든 active frame은 0…4,799 연속, SDK 캡처 unity frame 간격 1, 유한 위치, root 입력 차이 0이었다. 세션별 입력 clock/Animator/SDK 상태 전체를 기록한 것은 아니다.

패딩한 가상 capsule 자체에는 여전히 음수 간격이 있다. 따라서 표현은 **“원래 보호면 침범을 패딩 여유로 방지했다”**이며 “SDK 콜라이더가 완전한 비관통을 보장한다”가 아니다. 최소 여유가 얇기 때문에 추가 FPS/큰 이동/실제 클라이언트까지 자동 합격으로 처리하지 않는다.

동일 입력 공정쌍의 원래 보호면 개선은 Head −0.025182→+0.229315mm, Neck −0.156529→+0.135373mm다. 변경은 접촉 근처 헤어에 국한되며 해당 쌍의 모든 헤어 본/끝점 위치 차이는 최대 0.693899mm, RMS 0.020892mm였다. 넥타이는 위치·로컬 회전 모두 0 차이다.

## 반복 움직임 편차

| 비교 | 헤어 최대 / RMS (mm) | 넥타이 최대 / RMS (mm) |
|---|---:|---:|
| Original ↔ OriginalRepeat | 1.543149 / 0.045866 | 0.224389 / 0.031056 |
| FirstFinal ↔ Final | 1.848745 / 0.046203 | 0.224389 / 0.031056 |
| Final ↔ FinalRepeat | 1.543149 / 0.045476 | 0.224389 / 0.031056 |

Final ↔ FinalRepeat의 헤어 최대 편차는 HeadYaw 101 frame, `hair_tip_02`에서 1.543149mm였다. 같은 비교의 구간별 최대는 HeadNod 0.100459, Translation 0.167881, StartStop 0.092072, Turn 0.206823, Bend 0.344141, Wind 0.146571mm였다. 따라서 편차가 바람 구간에만 생긴 것은 아니다.

입력 회전을 quaternion 상대 회전으로 다시 계산하면 Wind의 600 frame에서 hair_wind 최대 0.020788°, tie_anchor 최대 0.058697° 차이가 확인된다. 바람 밖 hair/tie anchor 입력 회전 차이는 약 3e−12° 이하인데도 동적 본 편차는 발생했다. **Animator 위상 차이만으로 전체 원인을 확정하지 않는다.** first trial은 Start에서 생성되고 다음 trial은 Update에서 생성되는 코드 경로 차이, SDK 초기화·적분 상태 등을 추가 분리할 여지가 있다. 현재 기록만으로 특정 SDK 결함이라고 단정할 수 없다. ±1/±2 frame 이동 비교로 바람 차이가 완전 해소되지도 않았다.

## 보고서 및 재현 주의

- `StartNext()`는 `name.Replace("Repeat", "")`로 실제 Final/Original 프리팹을 로드한다. JSON의 `source` 문자열은 trial 이름을 그대로 넣어 `...FinalRepeat.prefab`처럼 존재하지 않을 수 있는 이름을 기재한다. 실제 로딩 코드와 구분하여 문서화한다.
- 같은 입력/같은 root라고 쓸 때 phase/root만 일치하는지, 실제 anchor local rotation까지 일치하는지 나누어 써야 한다.
- 추가 반복 실험이 있다면 첫 후보를 비교에서 숨기지 말고 현재 3회 후보 범위 +0.072…+0.135mm Neck 여유를 그대로 보존한다. 완전한 결정적 재현성을 목표로 한다면 생성 시점을 통일하고 Animator state/normalizedTime 및 SDK 초기화 상태를 기록해야 한다.
- 이번 작업은 수치 독립 검토이며 영상 시각 합격이나 새 표면 교차 검사를 수행한 것으로 쓰지 않는다.
