# 자세키 실험의 출처 정정

`bianca_CONNECTED_COAT.blend`는 실제32773정점 연결 사본이다. 그러나 초기 `bianca_CONNECTED_SIDE/FRONT.blend`는 이름과 달리34597정점의 원래 v041 연결 상태에서 만들어졌다. Python 함수의 기본 path값이 정의 시점의 SOURCE에 고정되어, 외부 SOURCE변수를 잠시 바꿔도 기본 호출 경로가 바뀌지 않은 것이 원인이다.

따라서 초기 CONNECTED_SIDE/FRONT 그림을 연결 사본에 자세키를 적용한 결과로 해석한 설명은 정정한다. 이 파일들은 자동 구동·최종 통합 전에 진단 중이었으며 최종 채택하지 않았다. v048의 Corrective Smooth는 연결 사본을 명시적 경로로 로드했으므로 해당 출처 오류와는 별개다. v051 첫 노멀 비교도 초기 CONNECTED_SIDE를 읽었으므로 분리된 정점이 남아 있는 원래 구조의 비교였다. Weld가 아무 정점도 합치지 않았다고 해석하면 안 된다.

공통 load는 실행 시점의 SOURCE를 읽도록 바꾸고 자세키 함수에는 명시적인 source인자를 추가했다. 이후에는 원본 경로·SHA·정점 수·component속성을 같이 기록한다. `02_correct_source.py`의 TRUE_SIDE/TRUE_FRONT는 실제32773정점 및 component속성을 단언한 뒤 저장한다. 기존 오표기 실험은 이력으로 보존하고 덮어쓰지 않는다. 손 v046은 모든 수정 출발 사본을 명시적으로 읽었으며 이 출처 오류에 영향받지 않았다.
